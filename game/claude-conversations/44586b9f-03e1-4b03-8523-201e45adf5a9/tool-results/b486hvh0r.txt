# 23 — Камера: слежение, кооп-рамка, блокировки, перехваты, тряска

## Цель

Камера сверху не мешает: в одиночной игре она намертво привязана к игроку (никакого плавания), в коопе мягко догоняет середину между игроками и не даёт им разойтись дальше экрана, в боссовых залах и сценах переходит под управление сценария и возвращается. Срез: одна ортографическая камера, три режима слежения, очередь перехватов и тряска (03).

Отличия от референса (одной строкой): все таймеры камеры — в тиках симуляции, не на реальном времени; тряска — событие в очереди (03); «блокировки по осям» — одно поле `axis_lock: none | x_fixed | y_fixed`, а не два булевых флага.

## Поведение

### 1. Цель слежения

1. Цель камеры — среднее арифметическое «точек камеры» всех **живых** игроков. Точка камеры — отдельная метка на игроке (обычно в его позиции).
2. **Вес босса.** Пока в зале есть боссы: цель = `(2·Σ игроков + Σ боссов) / (2·n + m)`. Соло против одного босса: ⅔ игрок + ⅓ босс — камера чуть смещается к противнику.
3. Некоторые арканы (усиленный выпад, прыжок-удар) **отцепляют точку камеры** от игрока на время арканы: камера не следует за рывком; по окончании точка возвращается на то же смещение, камера в соло прыгает на игрока мгновенно.
4. **Прицел камеру не двигает.** Упреждения по направлению прицела/движения нет: ни сдвига к курсору, ни «вперёд на скорость».
5. Нет ограничения камеры границами комнаты. Края видимого мира держат стены этажа (07, рамка 4/2 клетки); в залах боссов горизонталь заперта (см. §5).
6. **Состояния слежения.** (а) Если живых игроков 0, обновление камеры не выполняется — камера замирает на последней позиции (исключение — ветка «слежение выключено + привязка к стартовой точке»). (б) Флаг «привязка к стартовой точке» (точка = позиция камеры при создании): при выключенном слежении камера каждый кадр ставится в эту точку (используется на титуле). (в) При загрузке этажа флаги блокировок, перехвата, слежения и привязки сбрасываются, только если включён флаг «сбрасывать камеру при загрузке» (в игре включён всегда). (г) Залы боссов и концовок (кроме финального босса): камера ставится в (0; 1), включён режим «только вертикаль» (`x_fixed`); в финальном зале замки задаёт обработчик боя параметрами перелёта. (д) Слежение выключается также на титуле, в музейном обучении, у алтаря концовки, в стартовой фазе PvP и во вступлении босса.
7. **Условие «игрок мёртв»** для камеры: у любого активного игрока имя текущего состояния содержит метку смерти (в том числе во время анимации смерти). Тогда расстояние между игроками считается равным −1: запреты движения снимаются, телепорт не выполняется, слежение жёсткое (§2.3).

### 2. Сглаживание

1. **Соло:** позиция камеры = цель, каждый кадр, без сглаживания.
2. **Кооп** (оба живы): каждый кадр `позиция += (цель − позиция) × min(1, 12 · dt)` — экспоненциальный догон, постоянная времени ≈ 0.083 с, ≈95% за 0.25 с.
3. Если один из игроков мёртв (§1.7), расстояние считается недействительным (−1) и камера в коопе возвращается к **жёсткому** слежению за живым (резкий скачок). Догон включается только при расстоянии > 0.
4. Пока идёт тряска, камера сохраняет зафиксированное смещение «цель − позиция» (§6): догон возобновляется только после тряски.

### 3. Кооп: потолок разброса и телепорт

1. Пока **евклидово** расстояние между игроками ≤ 14 м, никаких запретов нет: все ранее выставленные запреты движения снимаются. Пределы по осям заданы в данных префаба камеры (14 по Y и 26 по X); значения по умолчанию в коде (15 / 25) перекрыты префабом — действуют значения префаба (Источник: data/extra/extra_values.json, camera).
2. При расстоянии > 14 м проверяются оси **независимо**: если `|dy| > 14`, верхний не может идти вверх, нижний — вниз, иначе снимаются только запреты по Y; если `|dx| > 26`, правый не может идти вправо, левый — влево, иначе снимаются только запреты по X. Итого: по горизонтали разлёт ≤ 26 м, по вертикали ≤ 14 м — игроки не расходятся дальше видимого поля (26.25 × 14.77 м, §10). Пример: dx = 27, dy = 5 (расстояние 27.5 > 14) — запрещено только расхождение по X; dx = 10, dy = 13 (расстояние 16.4) — запретов нет.
3. При расстоянии **> 32 м** живой доступный второй игрок телепортируется к первому. Якорь — позиция игрока с индексом 0 независимо от порядка обхода (в референсе при обходе «нулевой игрок позже» цель оказывается (0;0) — дефект, у нас не копируется). Ветка кооп-запретов и телепорта выполняется только вне PvP.
4. Зум в коопе не меняется.

### 4. PvP

PvP определяется флагом режима **или** именем активной сцены, содержащим метку PvP. Камера ортографическая; размер камеры = `max(базовый 7.3828125, расстояние_между_игроками × 0.42)` и пересчитывается каждый кадр: при сходящихся игроках размер возвращается к базовому. Цель — среднее живых; запретов на расхождение и телепорта нет (это отдельная ветка, §3). В начале раунда слежение выключается, камера ставится в центр арены (0; 0) (13).

### 5. Блокировки осей

1. `y_fixed` (только горизонталь): вертикаль камеры фиксируется на текущем значении в момент включения. `x_fixed` — наоборот.
2. Залы боссов и концовки включают `x_fixed`: камера стартует в (0; 1) и следует только по вертикали (по среднему с боссом).
3. Любой перехват (§6) может по завершении включить/выключить обе блокировки; нейтральное состояние после сцены — то, что было до неё.
4. Сброс: при загрузке этажа все блокировки, перехваты и «отключение слежения» снимаются.

### 6. Перехваты и сцены

1. **Перелёт** `fly(цель, T, следить?, замки?)`: слежение выключено; каждый шаг камеры (1/60 с = 2 тика; камера — слой отображения) позиция сдвигается на долю `t = прошло/T` оставшегося пути, `t` растёт 0 → 1; в последнем шаге — ровно в цель. Следствие: старт «с места», основной пролёт приходится на отрезок ≈ 0.07–0.25·T, потом камера стоит в цели (при T = 2 с: 32% пути за 0.17 с, 81% за 0.33 с, 98% за 0.5 с). Время шага — игровое (на паузе перелёт стоит). Длительность по умолчанию 1 с.
   - **Цель на шаге:** объект (его позиция читается каждый кадр) или точка; при «следить» — среднее живых игроков. Без объекта и без «следить» при замках одна ось продолжает следовать за игроками (X — если замок вертикали включён, а горизонтали нет; Y — наоборот), остальная — константа. Вызов без цели и без «следить» игнорируется.
   - **Замки перелёта:** при смене замков оба замка сначала снимаются; после конца перелёта замок «только горизонталь» = аргумент «вертикальный статус», замок «только вертикаль» = аргумент «горизонтальный статус» (имена перекрёстные; замок фиксирует текущую координату камеры в момент включения).
   - **Пока перехват активен**, обычное обновление камеры не выполняется вовсе: не сбрасывается размер камеры, не пересчитываются запреты кооп-движения (флаги остаются как были).
2. **Прерывание, а не очередь.** Новый запрос при идущем перелёте **прерывает** предыдущий: тот мгновенно ставит камеру в свою последнюю цель, применяет свои замки и завершается, затем стартует новый. Запрос игнорируется только если смена замков не задана, а обе оси уже заблокированы. Счётчик перехватов статический, режим «перехват» снимается при загрузке этажа. В референсе при **трёх** одновременных запросах счётчик не опускается ниже 2 и камера зависает в режиме перехвата (дефект) — у нас: одновременно активен один перелёт, избыточные запросы прерывают предыдущий по тому же правилу, зависание невозможно (критерий 5б).
3. **Подавление тряски.** Тряска (03) не стартует, если одновременно: (а) флаг «перелёт следует за игроками» истинен (по умолчанию истина; выставляется последним перехватом и **не сбрасывается** после его конца), (б) нет ни одного замка оси, (в) расстояние между центром игроков и камерой > 3 м. Следствия: в залах боссов (замок включён) тряска работает; после перехвата с «следить = нет» флаг ложный и тряска разрешена всегда; флаг пересчитывается только в ветке «слежение включено» (при выключенном слежении действует устаревшее значение). Уже идущая тряска не прерывается.
4. **Вступление босса (с диалогом):** игроки на паузе → перелёт к точке босса + смещение за 2 с (финал — 1.5 с) → пауза 1 с → босс появляется неуязвимым, числа урона скрыты → пауза данных → диалог → выход босса из вступления → 0.5 с → перелёт назад к сохранённой позиции за 2 с (финал — 1.5 с), замки восстановлены, ожидание, пока камера летит → игроки снимаются с паузы → босс в готовность, неуязвимость снята, включается боевая музыка (10).
5. **Вступление без диалога:** пауза 1 с → выход вступления → камера назад за 0.25 с с возвратом слежения (если нет замков) → 0.5 с.
6. **Концовка:** слежение выключено, камера за 18 с плывёт к точке 5 м выше предмета-победы; затем тряски ×0.5 и ×0.75 и ×1, вспышка (11).

### 7. Тряска (связь с 03)

1. Параметры — 03 §2–3: базовая сила 12, длительность 0.15 с, шаг 0.0166 с, не более 4 одновременно.
2. Множитель «тряска» в настройках = ползунок × 2 (0…2; по умолчанию 1 при ползунке 0.5); 0 выключает.
3. **Не накапливается (проверено по коду `CameraController`: `Update` и `Shake`):** камера каждый кадр сбрасывается в «цель − зафиксированное смещение», а каждая идущая тряска добавляет один шаг за кадр (одновременных до 4, п.4); видимое смещение порядка `12 × k × 0.0166` = 0.2 м при k = 1 (≈ 3 пикселей при 16 пикс/м). Смещение фиксируется один раз, в первом кадре тряски, вместе с её первым шагом. Это то же поведение, что описано в 03 §3 (оба файла приведены к коду).
4. **Геометрия шага.** Шаг — вектор **фиксированной длины со случайным углом** (угол равномерный 0..2π; длина `12 × k × множитель настроек × 0.0166` ≈ 0.199 м при k = 1, множитель 1), а не случайная точка квадрата. Шаги идут с паузой 0.0166 с (не чаще кадра). Одновременные тряски **суммируют** шаги в одном кадре (до 4 → до 4× за кадр; между кадрами не накапливается, так как позиция каждый кадр сбрасывается). Множитель настроек применяется в момент старта тряски. Флаг «игнорировать счётчик» обходит лимит 4, но счётчик всё равно увеличивается. Зафиксированное смещение «цель − камера» запоминается при первом шаге серии и сбрасывается, когда счётчик вернулся к 0 (если камера строго в (0;0;0), запоминается заново каждый кадр). Рандом шага — отдельный поток вне sim-хеша (24).
5. Силы событий вне урона: касание разрушаемого ×0.125, портал появления ×0.1, валун ×0.3, удар черепа алтаря ×0.3, финальные удары концовки ×0.5 / ×0.75 / ×1, взрыв паука ×2, ульта и события ×1.

### 8. Привязка к пикселям

1. Единица — один пиксель спрайта: 16 пикселей на метр, 0.0625 м.
2. Правило округления: по модулю позиции (знак сохраняется), доля пикселя `> 0.5` округляется вверх, иначе вниз (ровно 0.5 — вниз).
3. Нашему проекту: итоговая позиция камеры, отдаваемая рендеру, кратна размеру рендер-пикселя, а тряска и сглаживание считаются до округления; при отключении привязки допускается подпиксельный сдвиг.

### 9. Параллакс фона

На этапах с «небом» (воздух и молния) фон — слои облаков: смещение слоя = `(старт − позиция игрока 0) / 48`; у заднего слоя по Y — `/ 54`. При блокировках в формулу подставляется **нулевая координата игрока** по заблокированной оси, поэтому смещение слоя по ней равно константе `старт/48` (передний слой) или `старт/54` (задний по Y): при горизонтальном режиме (Y заблокирован) по Y = −5.625 (старт Y = −270), при вертикальном (X заблокирован) по X = 5.58 (старт X = 268). Точка старта — начало этажа (268; −270); для тестовых сцен — зона появления игрока, для PvP-арены — стартовая точка первого игрока. Слои следуют за **игроком 0**, а не за камерой, и обновляются, только когда его позиция изменилась; при выключенном слежении или привязке к старту — стоят. Цвет фона камеры: небо воздуха (146, 174, 174), молнии (19, 29, 36) — арт-ориентир; при выходе из сцены такого типа (обычной или босс) фон возвращается к чёрному. Слой облаков зеркалится по X с вероятностью 50 % при создании (сидируемый RNG), слои на Z = 10; эффект включается/выключается вместе с объектом.

### 11. Красная рамка урона

При уроне по игроку вспыхивает красная рамка по краю экрана: в соло — одна полноэкранная, в коопе — две отдельные (по игроку 0 и 1, каждая от своего урона). Анимация вспышки стартует с нормализованного времени `1 − clamp(урон / макс. HP × 5.5, 0.525, 1)` (формула — 03; раздельность рамок — здесь).

## Критерии приёмки

**Headless:**
1. Соло: позиция камеры = позиции игрока в каждом тике; никаких запаздываний при рывке.
2. Кооп: за 0.25 с камера проходит ≥ 94% расстояния до цели; при смерти одного позиция совпадает с живым в следующем же тике.
3. Игроки на расстоянии 27 м по X: правый не может идти вправо, левый — влево; на 15 м по Y: верхний не идёт вверх, нижний — вниз; на 26 м по X и 14 м по Y запретов нет. dx = 27, dy = 5: запрет только по X, запретов по Y нет; евклидово расстояние ≤ 14 (например dx = 10, dy = 9): снимаются все запреты. Расстояние 33 м: второй игрок телепортирован к первому; при мёртвом игроке — нет, слежение жёсткое. В PvP запреты и телепорт не выполняются, размер камеры = max(базовый, 0.42 × расстояние) и возвращается к базовому при сближении.
4. В зале босса цель = (2·игрок + босс) / 3; X камеры не меняется.
5. Перелёт T = 2 с при 60 шагах/с: остаток пути после 10 шагов 0.68 ± 0.03, после 30 шагов ≤ 0.03, после 120 шагов — 0 (точно); второй запрос во время перелёта прерывает первый: камера мгновенно в цели первого (замки первого применены), затем летит ко второй; три запроса подряд не зависают — после последнего перелёта режим перехвата снят. Пока перехват активен, размер камеры и запреты кооп-движения не пересчитываются.
6. Подавление: слежение «следить» + замков нет + камера дальше 3 м от центра игроков → тряска не стартует; в зале босса (замок включён) — стартует; после перехвата с «следить = нет» — стартует всегда. Отклонение ≤ 0.2 м за кадр при k = 1 (шаг — фиксированная длина ≈ 0.199 м, угол случайный); две одновременные тряски — до 0.4 м за кадр.
6б. Нет живых игроков → камера не двигается. Привязка к стартовой точке при выключенном слежении ставит камеру ровно в неё.
6в. Фон неба и параллакс: при X-замке слой по X = 268/48 = 5.58 (передний), при Y-замке слой по Y = −270/48 = −5.625; слои следуют за игроком 0.
7. Пиксельная привязка: 3.03125 → 3.0; 3.04 → 3.0625; −3.04 → −3.0625; 0.0 → 0.0; результат кратен 1/16.
8. Один сид + одни входы = один хеш.

**Визуально (видео):** соло — рывок читается без «резинки»; кооп — разведение читается как плавный догон; вступление босса — перелёт ускоряется к цели, возврат без рывка.
