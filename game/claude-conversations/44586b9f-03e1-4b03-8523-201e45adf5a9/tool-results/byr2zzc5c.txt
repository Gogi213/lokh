# 08. Расстановка врагов

## Цель

Плотность боя в комнате определяется формулой, а не ручной расстановкой: чем больше пол, тем больше «стоимости» врагов, но состав собран из готовых групп, поэтому комната читается (ядро в центре, мелочь по краям). Одна комната из трёх — «выживание»: двери запираются, враги идут волнами. В конце этажа — обязательный бой с элитой (запускает игрок у алтаря). Срез: любая сгенерированная комната (07) получает врагов по бюджету; плотность проверяется симуляцией.

Отличия от референса (одной строкой): все константы (шансы, коэффициенты, цены, веса) — в `data/encounters.json`, не в коде; вес добавки — явная колонка, а не усечённая разность; пул «выживания» содержит только волновые группы (в референсе в нём лежат и обычные, из-за чего реальная доля выживания ниже 35%); первая волна стартует с общей задержкой, а не с перекосом «первый враг позже остальных».

## Поведение

### Бюджет комнаты

`B = число_клеток_пола × k`, где `k = 0.08` (кооп — `0.125`). Считаются только клетки с полом (ямы и стены не в счёте). Для 16×12 с ~150 клетками пола: `B = 12`.

### Цены врагов

|Враг|Цена|Враг|Цена|
|---|---|---|---|
|Слизень|0.5|Мечник|2|
|Плеватель, катыш|0.75|Копейщик|2.5|
|Гуль, зональный|1|Лучник, маг|3|
|Турель, орбы|2|Разбойник, призыватель, любой стихийный|4|
|Большой гуль, гроб, каменный страж|4| | |

Цена группы — сумма цен. Элита и миньоны в бюджет не входят.

### Алгоритм «ядро + добавки»

1. **Выбор режима.** С шансом **0.35** комната «выживание» (берётся пул выживания), иначе обычный пул ядер.
2. **Выбор ядра.** Из трёх размеров рамок (4×4, 6×6, 8×8) остаются те, что физически помещаются в комнату (все клетки рамки — пол, отступ от краёв: 4 клетки сверху/снизу, 2 слева/справа). Размер выбирается с весом = числу групп в этом размере (4×4 — 15, 6×6 — 15, 8×8 — 10); затем группа — равновероятно.
3. **Стоимость.** Ядро всегда ставится, даже если дороже бюджета (комната не пустеет); его цена идёт в «потрачено».
4. **Добавки** (если ядро их допускает):
   - обычная комната: `n = int(clamp(B / (потрачено + 1), 0, 2))`;
   - выживание: `n = random(0..2)`, в коопе `random(1..4)`;
   - нет ядра, но влезают добавки: `n = 4`, комната «выживание» с шансом 0.5.
   Цикл по `n`: с шансом 0.2 остановиться (не при первой добавке без ядра); выбрать добавку по весу; если `B − потрачено − цена < 0` — **остановиться совсем**; иначе добавить и учесть цену.
5. **Веса добавок:** вес = `int(|5 − цена группы|)` (5 — «максимальная цена одиночной добавки»): слизень 4, гуль 4, зональный 4, мечник 3, копейщик 2, лучник 2, маг 2, разбойник 1, призыватель 1, стихийный 1. Базовый пул добавок — 8 групп (слизень, гуль, мечник, копейщик, лучник, маг, разбойник, призыватель). На стихийном этапе поверх них БЕЗ удаления нейтральных добавляются: 6 стихийных вариантов (цена 4, вес 1), плеватель и катыш (цена 0.75, вес 4 каждый) и зональный враг этой стихии ТРИЖДЫ (напрямую, из списка слизня и из списка турели; после вычёркивания чужих стихий остаются 3 записи по 4 → суммарный вес зонального 12, а не 4). Элита и миньоны в пул не входят. Нет ядра и нет добавок — комната пуста. Источник: EnemyDecorator.cs:PopulateAvailableDecoList, LoadElementalEnemies.
6. **Подмена на стихийных.** Подмена разыгрывается не на каждый спавн и не на каждую комнату по отдельности, а при (пере)инициализации декоратора: один раз на уровень (вход в генерацию) и ещё раз на каждую сгенерированную комнату; результат фиксируется в списках групп и используется до следующей инициализации. Если этап стихийный: каждый член ядра, имеющий стихийный аналог (мечник, лучник, маг, разбойник, копейщик, призыватель; слизень → плеватель/катыш/зональный; турель → зональный), заменяется им с шансом **0.55**. Для слизня и турели аналог выбирается РАВНОМЕРНО из полного списка (слизень: плеватель, катыш и все 5 зональных любой стихии; турель — 5 зональных); после подмены группы с врагом чужой стихии вычёркиваются целиком — поэтому группа из 4 слизней на стихийном этапе исчезает с вероятностью ≈ 0.78. Состав пула добавок на стихийном этапе — в п. 5. Источник: EnemyDecorator.cs:InitEnemyGroupDict, LoadElementalEnemies, UpdateEnemyDictWithElements, CleanAllEnemyGroupDicts; LevelGenerator.cs:Generate; Room.cs.

### Размещение

- Ядро — в центре комнаты, если рамка там помещается, иначе в случайной допустимой клетке. Первые `centerCount` (0–4) врагов ядра стоят в центре: 1 — в точке, 2 — слева/справа на ¼ ширины рамки, 3–4 — по окружности радиусом 20% рамки. Остальные (добавки ядра) стоят в случайном УГЛУ рамки со вставкой внутрь на `1 − int(centerCount / 4)` клеток (1 при центре < 4, 0 при центре 4), знак по каждой оси случайный; 4 попытки на каждого, если все совпали с занятыми клетками — враг не ставится. Источник: EnemyDecorator.cs:SpawnEnemies.
- Добавки без ядра: случайные точки внутри рамки 4×4, минимум 0.25 м друг от друга, 4 попытки.
- Враги появляются «спящими» (в `IDLE`, не в тревоге); внутри комнаты — тревога по правилам 06.

### Группы-ядра (центр. — число врагов в центре)

Обозначения: М мечник, Л лучник, Мг маг, Р разбойник, К копейщик, П призыватель, Сл слизень, Г гуль, БГ большой гуль, Гр гроб, Ст каменный страж, Т турель.

**4×4 (15):** центр 1 — БГ; Гр; Ст; Мг+М; Л+Р; Т+2Г; К+2Г. Центр 2 — М+Р; 2Мг; 2Л; Л+К; 2Р. Центр 4 — 4Сл. Центр 3 — 3Г; 3М.

**6×6 (15):** центр 1 — БГ+2Г; П+2Г; Л+2М; К+2М; Р+2М; Мг+2М. Центр 2 — 2Гр; 2К; Гр+К; Л+Р+2Г; 2Мг+2Г. Центр 3 — 3М+2Г; Гр+2Мг; Ст+2Т; 3Т.

**8×8 (10, без добавок):** центр 1 — Ст+П+2Г; Ст+К+2Г. Центр 2 — 2БГ+4Г; 2Л+2М; 2П; 2Мг+2М. Центр 3 — 6Г; П+2Гр; К+2Гр. Центр 4 — Л+Мг+М+Р.

**Выживание 4×4:** обычные (без волн) — {М, К, Мг, Л, Р}+2Г; волновые — 4Сл; 2Сл+2Г; 3Г; 2М; 2К; 2Мг; 2Л; 2Р; П+2Г; БГ+2Г. **6×6 (волновые):** 2Г+Т+2М+Л; 3Г+2Р; 2Г+Р+2М+К; 4Г+3М; 2Г+3БГ; 2Мг+2П; 2Мг+2Л; 2Сл+2Т+2Г+Л; 2П+2Г+2М (6 врагов, центр 3); 5Сл+Гр+3Г (две последние группы допускают добавки). **8×8:** 2Г+Т+2М+Мг+2Р+Л; 2Т+2Мг+2П; 3Г+3М+2К; М+2Г+3БГ+2Гр+Ст; 2Сл+2Г+2Гр+2Г+2К+2Г.

### Комнаты выживания

- Группа делится на **волны** по `N` врагов: `N = centerCount`, если он > 0, иначе 4; если остаток после деления на 4 равен 1 — волна одна на всех (без одиночки в хвосте). Добавки группы — не волны: стоят в комнате с начала.
- Игрок заходит во внутреннюю часть комнаты (размер комнаты −2 по обеим осям) → **двери запираются**, звук блокировки, точка возрождения = место входа; в коопе остальных игроков телепортируют к вошедшему.
- Враги волны появляются из порталов в случайных допустимых клетках (минимум 2 клетки от центра, разные клетки), сразу «в тревоге» с радиусами 999 (преследуют всегда; безусловность 999 в коде расстановки не видна — открытый вопрос 6). **Каденс:** враг № `j` волны появляется через `j × 0.125 с` после старта волны; к первой волне общая задержка 1.0 с. Следующая волна стартует в тот же кадр, когда **убит последний** враг предыдущей.
- Последняя волна зачищена → двери открываются, эффект победы; с шансом **0.25** — малый сундук в центре.
- Все игроки мертвы → комната сбрасывается: непогибшие враги удаляются без добычи, прогресс волн обнуляется, двери открываются, триггер взводится заново.

### Режим «двойные враги»

Включается предметом. Каждый поставленный враг получает копию в случайной точке ОКРУЖНОСТИ радиусом 1.5 м (не внутри круга); в коопе — две копии. На каждого врага накладывается множитель HP ×0.8 (мод «множитель −0.2»); враги с «заменой» HP (элита, боссы, миньоны призыва) его игнорируют. Источник: EnemyDecorator.cs:SpawnEnemies; EnemyCountUp.cs. Волны выживания: каждый портал спавнит за **2 цикла** (кооп — 3) с интервалом 0.25 с в квадрате 1.5×1.5. Общее число врагов этажа (для счётчика) увеличивается соответственно. При «двойных» генератор этажа всегда выбирает комнату случайно из всего пула (обычно — с шансом 0.3); см. 07.

### Кооп

Бюджет `k = 0.125` (×1.5625); добавки в выживании `1..4` вместо `0..2`; «двойные» — 3 врага вместо 2; циклы выживания 3 вместо 2; щит финального босса ×2 (300 → 600); цель обычного босса — случайный живой игрок (финальный чаще берёт ближайшего, 10 §Кооп).

### Элита

Элита не ставится в комнатах. Это **обязательный бой в конце этажа**, запускаемый игроком: портал выхода открывается только после победы, а когда активировать алтарь — решает игрок; у выхода стоит алтарь с тремя черепами, шкала — доля убитых врагов этажа (`убито / всего`). Черепа гаснут на 30%, 60% и 90%. Игрок активирует алтарь → `u = 1 − доля` (не убитое):

- Тип элиты: список из 7 групп (мечник, копейщик, маг, призыватель, разбойник, лучник, гроб); индекс следующей = `(прошлый + random(1..6)) mod 7` — **два раза подряд один тип не выпадает** (счётчик живёт весь забег).
- Группа: элита всегда первая; добавки в порядке «с начала списка», затем перемешиваются: мечник → мечник, копейщик, 3 гуля; копейщик → копейщик, мечник, 3 гуля; маг → маг, призыватель, 3 гуля; призыватель → призыватель, маг, 3 гуля; разбойник → разбойник, лучник, 3 гуля; лучник → лучник, разбойник, 3 гуля; гроб → гроб, большой гуль, 3 гуля. Первые две добавки — пара из двух РАЗНЫХ классов, а не «два одноклассника» (кроме мечника/копейщика). **Добавок: `5` при `u > 0.7`, `4` при `u > 0.4`, `3` при `u > 0.1`, `2` иначе** — берутся с начала списка (сперва пара классов, потом гули), порядок перемешан.
- Подмена на стихийных: шанс `0.5 × u` для каждой добавки; применима только к шести базовым классам — сама элита, гроб, большие гули и обычные гули не подменяются. Источник: ExitRoomEventHandler.cs:miniBossGroupList, RollForElemental.
- Появление: элита в центре через 1.5 с, добавки по кругу радиусом 6 м с задержкой `1.5 + random(0.1; 0.5)` с; добавки без добычи и без вклада в статистику. Награда — сундук элиты (09).

### Элита: активация, зал и итог боя

- **Активация.** Кнопка взаимодействия в радиусе 2.0 м от круга-активатора; одноразово; подсказка скрывается, если игрок мёртв или ушёл. Алтарь «ломается»: 0.5 с темнота → по 0.2 с на каждый горящий череп (+0.1 с) → разлом; состояние черепов отражается на алтаре и на круге (прозрачность 0.25 у погашенных).
- **Зал.** Арена 16×12 вокруг центра выхода; элита создаётся с задержкой 1.5 с в центре; все её враги — без добычи и без вклада в статистику убийств; пока идёт бой, порталы выхода, лавок и старта скрыты.
- **Итог.** Заморозка кадра; надпись победы через 0.5 с; сундук элиты (в гонке боссов — его вариант гонки, 19 §4) через 1.25 с на 5 м выше точки выхода; выходной портал — через 3.5 с после зачистки (круг на 3.5 с). Боковые порталы (смещения x/y от точки выхода: старт этапа −3.5/4, лавка предметов −6.5/2, лавка арканов 6.5/2, особая комната 3.5/4) создаются после обнаружения выхода, только вне гонки боссов и только если бой уже зачищен или не начат.
- **Предметы-локаторы.** «Благословенный» — элита без добавок; «проклятый» — добавки заменяются ШЕСТЬЮ стихийными вариантами (по одному на класс), шанс подмены 1.0, на окружности радиуса 6.
- **Доля убитых.** `убито / всего`, зажатая в [0; 1]. Числитель растёт при смерти ЛЮБОГО врага (включая миньонов и добавки элиты: флаг «не считать в статистике» влияет лишь на статистику игрока); знаменатель — только расставленные враги (с копиями «двойных» и врагами выживания). В гонке боссов и при нуле врагов доля = 1.0 → `u = 0` → добавок всегда 2 (не 5).

Источник: MiniBossActivationCircle.cs:Update, Activate; MiniBossAltar.cs:FlashSkulls; ExitRoomEventHandler.cs:Update, CreateTreasureChestDelayed, HandlePortalCreation, CreateSurvivalRoom; Level.cs:EnemyDefeatedPercentage; Enemy.cs:EnemyDeadState.OnEnter.

### Карточка появления

Враги, создаваемые фабриками (выживание, элита, призыв), создаются неактивными и включаются анимацией карточки. Обычная — карточка-аркана; для 11 типов (гроб, страж, большой гуль, суперслизень, 7 элит) — «мульти-карточка»: 4 карты с интервалом 0.1 с (анимация появления 0.75 / 1.33 с), затем переворот по 0.1 с (анимация 0.517 с), затем «призыв» (0.483 с), где включение врага — в t = 0 призыва. Реальная задержка активации поэтому больше заданного таймера фабрики (≈ 1.0–2.0 с). Враги, ставящиеся обычным декоратором комнат, карточек не используют. Источник: Enemy.cs:Spawn; Card.cs; MultiCard.cs; data/extra/anim_clips.csv, anim_events.csv.

### Фабрика врагов

«Зачищена» = была запущена, ничего больше не создаёт и все созданные ею враги в состоянии смерти. Сброс: незавершённые враги теряют добычу (и сундук), уходят в смерть или удаляются вместе с порталом. Режим «в тревоге с радиусами 999» включается только при поднятом у фабрики флаге автотревоги; в коде расстановки выживания флаг не выставляется (что в префабе фабрики — данными не видно). Источник: EnemyFactory.cs:AllEnemiesCleared, ResetFactory, Update; EnemyDecorator.cs:SpawnSurvivalRoom.

### Комната выживания: детали

- Проверка «все игроки мертвы» — раз в 1.0 с.
- Вход: точка-чекпоинт комнаты запоминается как «последний чекпоинт» всех игроков; остальных игроков телепортируют к вошедшему; ворота строятся по соединениям комнаты; убираемые стены комнаты активируются только на допустимых сторонах.
- У комнаты-волн один объект на волну; триггер размером «комната − 2» — только у первой; ворота открываются только после ПОСЛЕДНЕЙ волны (у промежуточных логика ворот пропускается). Награда — малый сундук по шансу 0.25, создаётся только если жив хотя бы один игрок, без стихийных вариантов лута.
- Опасности комнаты (ловушки): запускаются при входе, принудительно гасятся при зачистке и сбросе.
- Если для группы нет допустимой клетки — комната выживания не создаётся (комната остаётся пустой).

Источник: SurvivalRoom.cs:Update, Activate, Disable, ResetSurvivalRooms, EnableNextRooms; HazardRoom.cs; EnemyDecorator.cs:PlaceEnemyGroup, SpawnSurvivalRoom.

### Реестр модов забега

Мод забега заменяет мод с тем же ID, включается сразу при добавлении (если у него флаг немедленной активации), все моды снимаются при возврате в хаб; у модов есть хуки «после загрузки уровня» и «по завершении загрузки» (так работают «трудный забег», «случайный билд», гонка боссов — 17, 19). Перечень типов комнат — 07 §2; спавнеры NPC и рандомизатор вида NPC — 17/18. Источник: RunModifier.cs; RoomType.cs.

## Критерии приёмки

**Headless (симуляция 1000 комнат на сид):**
1. Для 16×12 с 150 клетками пола: средняя «потраченная» стоимость в обычных комнатах — не больше `B + 0.5×цена ядра` и не меньше `0.5·B`.
2. Доля комнат-выживания среди комнат, где ядро выбрано, = 0.35 ± 0.03; ни одного волнового ядра в обычной комнате и ни одной не-волновой группы в пуле выживания.
3. Добавок в обычной комнате ≤ 2; в выживании ≤ 2 (кооп ≤ 4).
4. Выживание: враг № `j` волны возникает на `j × 0.125 с` (±1 тик); следующая волна — на том же тике, что и смерть последнего; смерть всех игроков сбрасывает комнату.
5. Подмена: жеребьёвка даёт 55% ± 5% подходящих членов ядра стихийными (это свойство самой жеребьёвки, а не доли по комнатам: аналог слизня и турели выбирается равномерно, группа с врагом чужой стихии вычёркивается); чужой стихии в комнатах нет; результат подмены один на уровень и один на комнату.
6. Режим «двойные»: каждый поставленный враг даёт 2 экземпляра (кооп 3); кооп-бюджет ×1.5625.
7. Элита: 1000 боёв — число добавок соответствует таблице по `u`; два подряд одинаковых типа = 0.
8. Один сид = один хеш расстановки.
9. Вес добавки = `int(|5 − цена|)`; на стихийном этапе суммарный вес зонального в пуле 12, нейтральные добавки остаются в пуле.
10. Обычный пул ядер 6×6 содержит 15 групп; последняя волновая 6×6 без добавок — 2П+2Г+2М.
11. Элита: пара добавок после элиты — два разных класса (маг → маг + призыватель); в гонке боссов добавок ровно 2; доля убитых растёт и от миньонов.
12. «Двойные»: копия на окружности 1.5 м, HP ×0.8, у элиты и боссов HP не меняется.

**Визуально (скриншот):** комната с ядром в центре и добавками по краям; запертая комната выживания с дверями и порталами; алтарь с тремя черепами и гаснущей шкалой.

## Открытые вопросы

Закрыто:
1. Вес добавки при дробной цене (2.5) — явная колонка в `data/encounters.json` (технический выбор).
2. Перекос стартовой задержки первой волны — не сохраняем, общая задержка 1.0 с (наше решение, технический выбор).
3. Доля убитых при «двойных» и выживании — `убито / всего` с учётом копий.
4. Какие комнаты получают врагов (флаг «случайные враги») — флаг в данных комнаты (07 §1), по умолчанию — все боевые.
5. Размер сундука элиты и шансы наград — 09 §5.

## 5. Стихии

Шесть стихий: **огонь**, **вода**, **воздух**, **земля**, **молния**, **хаос**. Не использовать: холод, ветер (как стихию), гроза. Подстихии: **лёд** (у воды; цвет и заморозка), **яд** (у земли; статус яда), **растение** (у земли; корни). Статусы по стихиям: огонь — поджог, вода — заморозка, воздух — замедление, земля — яд (+ корни у растений), молния — шок, хаос — хаос-статус или все статусы (04, 05 §6). Цепочка уязвимостей: вода > огонь > воздух > земля > молния > вода (04 §18). Коды в нумерации 05c: ОГ, ВД, ВЗ, ЗМ, МЛ, ХА.

| **стихийный мечник / лучник / маг / разбойник / копейщик / призыватель** | 30 стихийных вариантов (5 стихий × 6 классов; хаос — нет) |
| **слизень** | прыгает; делится при D ≥ 1 |
| **малый слизень** | потомок слизня (не «мини-слизень», «мини-слизь») |
| **плеватель** | слизень-стрелок |
| **катыш** | слизень-накат |
| **слизень-матка** | элитный слизень (HP 500, при смерти делится на 15) |
| **гуль** | окружает |
| **большой гуль** | трёхударный |
| **гроб** | прыгает; элита-гроб — один из классов элиты |
| **каменный страж** | неоглушаемый тяжёлый враг; **элита-страж** — его элита |
| **турель** | неподвижный стрелок |
| **мимик**, **большой мимик** | притворяются сундуком |
| **циклоп** | враг с наводимым лучом |
| **лазерный шар** | HP 1, четыре луча |
| **орб-спутник** | см. §7 |
| **ядовитое растение** | неподвижный стрелок ядом |
| **паук-бомба**, **шипастый паук** | пауки |
