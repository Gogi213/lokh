# 09 — Лут, валюты, магазины

## Цель

Убийства и сундуки дают золото, кристаллы, сердца, реликвии и арканы по таблице данных; награда незаметно подстраивается под ход забега; магазины показывают честный выбор без повторов. Игрок не видит переключателей, но чувствует «справедливость»: потратил всё — дальше щедрее, лежит на золоте — скупее, на грани смерти — сердца падают чаще.

Отличия от референса (по одной строке):
- Референс бросает глобальный рандом — у нас каждый дроп считается из потока `hash(floor_seed, source_id, drop_index)`: тот же сид + те же убийства = тот же лут, лишний бросок где-то ещё его не сдвигает.
- Пул реликвий в референсе при пустом списке молча ничего не даёт (и 10% выпавшего «проклятого» броска пропадает) — у нас запасной пул.
- Поле «шанс заблокированной арканы» в референсе перевёрнуто (1 = не искать новую) — у нас поле `prefer_new_spell` читается прямо.
- Цены, тиры, группы исключений и константы лежат в данных (`data/loot.json`, `data/prices.json`, `data/relics.json`), не в коде.

## Поведение

### 1. Валюты

| Валюта | Живёт | Назначение | Предел |
|---|---|---|---|
| Золото | один забег (счётчик «собрано на этаже» сбрасывается каждый этаж) | магазины забега | нет |
| Кристаллы | между забегами | разблокировка реликвий и арканов в хабе; проклятая сделка | 999 |
| Сердца | подбираемое | лечение (величина подбора — в 01/02) | — |
| Души | только кооп, пока партнёр мёртв | оживление партнёра | — |

Золото падает монетами 1/5/10: пока остаток >0, монета выбирается равновероятно из {1}, {1 или 5, если остаток ≥5}, {1, 5 или 10 по остатку}.

### 2. Схема строки таблицы дропа

Одна строка на источник (класс врага, тип сундука, разрушаемый предмет). Все поля, кроме имени, необязательны.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `gold_rate` | 1 | шанс, что золото вообще выпадет |
| `gold_min`, `gold_max` | 0 | равномерное целое включительно |
| `gold_compensate` | true | применять подстройку (§4) |
| `crystal_rate`, `crystal_min`, `crystal_max` | 0 | см. §3 |
| `heart_rate`, `heart_min`, `heart_max` | 0 | число бросков §3 |
| `relic_rate`, `relic_min`, `relic_max` | 0 | число бросков |
| `spell_rate`, `spell_min`, `spell_max` | 0 | число бросков |
| `prefer_new_spell` | 1 | шанс сначала искать ещё не открытую аркану |
| `signature_rate` | 0 | шанс дать улучшенную версию аркана вместо новой |
| `soul_min`, `soul_max` | 0 | души (кооп) |
| `spell_list`, `relic_list` | пусто | сценарный дроп: выбор из списка |

Нормализация при загрузке: `max`=0 при `min`>0 → `max`=`min`; для кристаллов, сердец, реликвий, арканов при `rate`>0 и `min`=0 → `max`=1.

### 3. Расчёт количества

- **Золото.** С шансом `gold_rate`: целое из [min, max] × глобальный множитель (кооп +10%) × подстройка (если включена) → округление вверх. Золото без подстройки добавляется в счётчик `uncompensated`.
- **Кристаллы.** База = `crystal_min` (гарантия). С шансом `crystal_rate` база заменяется равномерным целым из [max(min,1), max]. Затем множитель этапа M = min(0.25 × сложность, 1), где сложность = круг×3 + номер этапа (0–2) + стартовая. Если количество >1 → floor(n × (1+M)); если =1 → 1 + плоский бонус + (1 с шансом M).
- **Сердца.** `heart_min` гарантированных + по одному броску на каждую единицу от min до max с шансом `heart_rate` × подстройка здоровья (§4).
- **Реликвии и арканы.** `min` гарантированных + по броску на каждую единицу до max с шансом `rate`. Число реликвий умножается на глобальный модификатор (1.0) с отбрасыванием дроби.

### 4. Подстройка наград

**Золото.** Работает, только когда побеждено ≥50% врагов этажа, иначе множитель 1. Пусть d = 1 − (золото_этажа − uncompensated) × 0.005. Если d ≥ 0: множитель = 1 + 0.5·d; иначе = 1 − 0.5·min(1, −d). Примеры: собрано 0 → ×1.5; 100 → ×1.25; 200 → ×1.0; 300 → ×0.75; ≥400 → ×0.5.

**Здоровье.** Берётся наименьшая доля здоровья среди живых игроков h; множитель шанса сердца = линейно от 1.75 (h=0) до 0.5 (h=1): 1.75 − 1.25·h. Гарантированные сердца множитель не трогает.

### 6. Реликвии: пул без возврата

Пул строится при каждой загрузке этапа заново (не раз на забег): из полного списка убираются стартовый, «победный», сборные (только по рецепту), нерозничные, уже имеющиеся у любого игрока, их исключения (§7) и компоненты уже собранных групповых реликвий.

Разблокировка: в пул входят открытые реликвии плюс до `locked_cap` (24) ещё не открытых, набранных по тирам от нижнего вверх (внутри тира случайно) — игрок видит новое, но не всё сразу. Тир 0–4 влияет на цену разблокировки, не на шанс выпадения; шанс равномерный.

Выбор: бросок против `curse_chance` (0.1 по умолчанию, одинаково для дропа и сундуков) → проклятый пул, иначе обычный; элемент берётся равновероятно и вычёркивается. Предел инвентаря — 12 реликвий, 12 проклятых.

Проклятый пул отдельно: проклятые реликвии минус нерозничные и только-хабовые. Особый «хаб-пул» проклятых служит сделке в хабе.

Отличие: референс при пустом выбранном пуле ничего не выдаёт; у нас пустой пул → запасной (другой пул), и только если оба пусты — нет дропа.

### 7. Группы исключений

- **Вытеснение:** владение реликвией A убирает из пула список B(A) (составная реликвия вытесняет свои части; сет вытесняет компоненты; комбинированная стихийная — обе родительские).
- **Взаимоисключение:** в каждом множестве можно держать только одну; поднятие второй сбрасывает остальные; если среди имеющихся есть проклятая — подъём отклоняется.
- **Группа:** в инвентаре компоненты группы считаются одним предметом; их по отдельности в пул не возвращают.
- **Сборная:** выдаётся только как недостающая часть рецепта.

### 8. Цены и тиры

Базовая цена из `prices.json`; отсутствует — 1. Распределение базовых цен референса (505 строк): 0 — 13%, 2 — 8%, 4–5 — 24%, 6 — 33%, 7 — 9%, 8 — 4%, 10 — 3%, 12 — 5%. Смысл: 2 — базовые приёмы, 5–7 — обычное, 10–12 — сильное.

| Цена | Формула |
|---|---|
| Золото | база × 25 |
| Кристаллы, реликвия | база + (тир+1) × 4, не ниже 10 |
| Кристаллы, аркана | база + clamp(тир,1,4) × 5, не ниже 10 |
| Кристаллы, улучшение аркана | 50 |
| Кристаллы, проклятая реликвия в хабе | 25 |

### 9. Магазин предметов

5 слотов реликвий (шаг 1.625) и 1 слот лечения. Слот реликвии:
1. с шансом 3% — недостающая часть рецепта сборной реликвии, если у игрока есть другая часть (проклятость должна совпасть);
2. иначе — из пула без возврата (учитывая уже выставленные в магазине);
3. шанс скидки `sale_chance` = 0.15: цена −25 золота (то есть −1 единица базы); у проклятых скидок нет.

Пустой пул — слот исчезает. Купить нельзя, если реликвия уже есть, инвентарь полон (12) или проклятых ≥12. Эффект «перезапуск витрины» заменяет проданный слот новым броском.

Лечение: лечит max(50, ⌈макс.здоровье × (доля − 0.05 × число_покупок)⌉) всем живым и оживляет мёртвых; доля из данных.

### 10. Магазин арканов

Слоты: обычная новая аркана (скидка 15%, цена база × 25) и «улучшенный» слот, у которого:
- с шансом 0.45 предлагается улучшение уже имеющейся (цена 100 золота);
- с шансом 0.35 (при круге ≥1) — аркана особого тира (0.75, если у игрока «победная» реликвия), цена база × 25;
- иначе новая улучшенная — база × 25 + 50.

Пул арканов: тиры 0–4; строится при загрузке этапа, из него убираются выбранные и надетые у любого игрока; вычёркивание после выбора. Пул ограничен: тиры добавляются снизу вверх, пока число ещё не открытых не достигнет `locked_cap` (24), дальше тиры не добавляются.

### 11. Выпадение арканы

Для каждого выпавшего по §3 экземпляра: с шансом `prefer_new_spell` ищется ещё не открытая аркана; если нет — любая из пула. Для сундука босса: `signature_rate` = 1 — выпадает улучшенная версия имеющейся арканы (сигнатурная, если есть, иначе усиленная); нет таких — обычная новая.

## Числа

Всё из таблиц выше в `data/loot.json`; общие константы: `gold_comp_scale` 0.005, `gold_comp_min/max` 0.5/1.5, `gold_comp_min_defeated` 0.5, `heart_comp_max/min` 1.75/0.5, `crystal_stage_step` 0.25, `crystal_cap` 999, `curse_chance` 0.1, `locked_cap` 24, `sale_chance` 0.15, `sale_discount` 25, `gold_price_mult` 25, `store_slots_items` 5, `recipe_chance` 0.03, `inventory_cap` 12, `coop_gold_bonus` 0.10. Свои цели: ≈60 реликвий (+10 проклятых), ≈20 арканов, 5 тиров.

## Критерии приёмки (headless)

1. Симуляция 100 забегов × 3 этапа × 2 стадии (фикс. сиды): ни разу реликвия не оказывается в инвентаре дважды; ни разу выдана вытесняемая при наличии вытесняющей.
2. На 100 000 убийств каждого класса частоты кристаллов, сердец, реликвий, арканов в пределах 3σ от таблицы §5 при фиксированных множителях.
3. Подстройка: монотонность множителя золота по собранному золоту, граничные значения 1.5 / 1.0 / 0.5 в точках 0 / 200 / ≥400; при побеждённых <50% — ровно 1; множитель сердца 1.75 при h=0 и 0.5 при h=1.
4. Кристаллы: сундук босса даёт 20/25/30/35/40 на сложностях 0, 1, 2, 3, ≥4.
5. Магазин: 1000 генераций — слоты различны, доля скидок 15%±3%, доля рецепта 3%±1.5%, ни одной скидки у проклятых.
6. Пул: один и тот же сид — тот же порядок выдачи; пустой выбранный пул переходит в запасной.
7. Все выставляемые в магазинах id имеют цену >0; `validate_content` ловит отсутствие.
8. Скриншот магазина с ценами и значком скидки.

# 11 — Забег: хаб → этапы → боссы → финал → титры

## Цель среза

Полный забег от старта до титров на заглушках: из хаба в три стихийных блока (два этажа и босс в каждом), затем финальный босс, концовка, возврат. Сложность растёт по одной формуле, смерть и победа ведут к своим экранам, прогресс сохраняется в нужных точках, таймеры считаются честно. Содержимое этажей, боссов и лута берётся из срезов 7–10; здесь — только каркас последовательности.

## Поведение

1. **Старт.** С титульного экрана новая игра ведёт в обучающую комнату, если она ещё не пройдена (один раз за профиль; после неё разовый подарок самоцветов), иначе в хаб. В хабе игрок свободно ходит, собирает билд (слоты приёмов, стартовая реликвия), тратит самоцветы, берёт модификаторы забега. Выход в забег — портал, который активен, когда в хабе присутствуют все присоединившиеся игроки.
2. **Порядок стихий.** Пять стихий: холод, земля, огонь, ветер, гроза. При начале забега список перемешивается сидируемым RNG, берутся первые три — это порядок блоков забега. Блоки не повторяются. Сид забега виден игроку и вводится вручную.
3. **Структура блока.** Блок = этаж 1 → этаж 2 → босс стихии. Счётчик этажа растёт при каждой загрузке этажа или босса; если счётчик после этажа больше порога `floors_per_block` (1), следующим грузится босс, иначе ещё один этаж той же стихии. После босса счётчик этажей обнуляется, номер блока растёт. Метка на экране: «блок-этаж» (1-1, 1-2, 1-3 для босса, затем 2-1…).
4. **Финал.** После третьего босса грузится финальный босс (метка «4-1»), после него — сцена концовки, затем титры, затем возвращение на титул или в эпилог при первом прохождении.
5. **Выход с этажа.** Подойти к порталу на расстояние ≤ 2 м, нажать «взаимодействие». Все игроки переносятся в точку портала, становятся неуязвимыми и не падают в ямы, портал закрывается (анимация), затем следует переход. Отойти дальше 2 м или умереть — подсказка гаснет.
6. **Итоги этажа.** Между этажами и после босса показывается экран итогов: время этажа, процент исследованной карты, золото и самоцветы этажа. Время заморожено. Кнопка «дальше» блокируется на 1.5 с, срабатывает по отпусканию. После финального босса экран итогов показывается один раз, перед концовкой.
7. **Формула сложности.** `D = петля × 3 + номер_блока(0…2) + стартовая_добавка`. Стартовая добавка 0, в «трудном забеге» 3. Для финального босса номер блока = 3. D пересчитывается при каждой загрузке этажа или босса.
8. **Что даёт D.**
   - Значение интерполяции `t = clamp(D × 0.5, 0, 1)`: замахи, паузы, перезарядки врагов и боссов сжимаются от «лёгкого» значения к «жёсткому» (например пауза босса 30→20 с, оглушение от удара 0.9→0.7 с).
   - Вариант «легендарный» у врагов открывается при D ≥ 4.
   - Прибавка здоровья врагам (обычный забег): `min(D × 20 − 10, 70)`, на D=0 — минус 10.
   - Множитель самоцветов с этажа: `min(D × 0.25, 1)`.
   - В режиме «масштабирование» (трудный забег, петля) вместо прибавки здоровья включается набор: здоровье `+5 × D` плоско, урон врагов `+3% × D`, перезарядки, замахи и выходы из атаки `−3% × D`, длительность оглушения боссов `−2% × D`; статусный урон не масштабируется.
9. **Трудный забег.** Покупается в хабе за самоцветы один раз за забег: `D` стартует с 3, включается режим «масштабирование». Сбрасывается при возврате в хаб.
10. **Петля.** После первой победы в хабе открывается петля (за самоцветы): номера блока и этажа обнуляются, счётчик петли +1, список стихий перемешивается заново, билд сохраняется, включается «масштабирование», запись забега идёт в режим «бесконечный».
11. **Таймеры.** Таймер этажа и общий таймер идут по тикам только на этажах и боссах, не в хабе, не на паузе и не на экранах итогов; замедление времени (hitstop) их не замедляет. Таймер останавливается на показе итога смерти и на победе над финалом. Общее игровое время профиля накапливается отдельно и пишется при сохранении.
12. **Смерть.** Игрок в `DEAD` не участвует в бою. Если у него есть реликвия возрождения — через 1.5 с появляется подсказка, по подтверждению он встаёт с 25% здоровья рядом с напарником. Иначе, если все игроки мертвы: пауза музыки, через 1.0 с таймер забега останавливается и появляется экран итога смерти с поэтапным показом (фон 0.5 с, пауза 0.5 с, затем строки: метка этажа, самоцветы, время, билды игроков). «Подтвердить» — в хаб, «отмена» — на титул. Падение в яму — не смерть: небольшой урон и возврат на последнюю безопасную клетку.
13. **Победа.** Смерть финального босса: выдаётся награда самоцветами (25), ставится флаг «пройдено» (открывает петлю и более редкий пул арканов), игроки уходят в портал со сдвигом 0.15 с, затем итоги этажа → концовка → титры. На экране итога победы вместо заголовка смерти показывается заголовок победы. Если общее время < 1500 с — метка «быстрое прохождение».
14. **Автосохранение.** Точки: перед каждой загрузкой сцены; при смерти игрока; при первом получении аркана/реликвии; при покупке в хабе; при победе над финалом; при выходе из хаба. Состояние посреди этажа не пишется — выход в меню во время этажа заканчивает забег (референс так же).
15. **Возврат в хаб.** Золото обнуляется, самоцветы остаются, модификаторы забега снимаются, мёртвые игроки встают с полным здоровьем (в коопе — по правилам 13-coop).

# 12 — Мета: валюты, пул разблокировок, история забегов

## Цель среза

Между забегами растёт не сила героя, а разнообразие: открытые арканы и реликвии попадают в пул наград следующих забегов. Две валюты с разной жизнью, правила открытия, правила формирования пула, запись лучших забегов. Готово, когда открытое в одном забеге появляется в пуле следующего (после перезапуска игры), а закрытое — нет.

## Поведение

1. **Две валюты.** *Золото* живёт в пределах забега: копится на этажах, тратится в магазинах забега, в хабе и при начале забега обнуляется, потолок 9999. *Самоцветы* переживают смерть и перезапуск игры, потолок 999, пишутся в сохранение; тратятся в хабе на открытие содержимого и модификаторы забега. Лишнее сверх потолка пропадает (сообщение игроку).
2. **Заработок самоцветов.** Падают с врагов и сундуков по таблице лута (срез 9); множитель этажа `min(D × 0.25, 1)` из 11-run-loop; стихийные враги платят больше. Подбор в пределах забега копится сразу, в сохранение попадает в точках автосохранения — не теряется при смерти.
3. **Профиль (хранится между забегами).** Самоцветы; открытые арканы (по id) и отдельно открытые «усиленные» варианты арканов; открытые реликвии; открытые облики; флаги (обучение пройдено, игра пройдена, видели ли персонажей-NPC); счётчики использования каждого аркана и числа ульт; статистика (смерти, золото, самоцветы, урон, падения в ямы, ловушки, уничтоженные предметы, побеждённые враги по типам); общее игровое время; сохранённые наборы билдов по 6 ячеек на игрока; настройки отдельно.
4. **Стартовый набор.** Небольшой фиксированный список арканов (базовая атака, рывок, один стандартный приём, один «сигнатурный») и одна реликвия открыты всегда и восстанавливаются при любой проверке профиля; список лежит в данных.
5. **Открытие аркана.** Аркан становится открытым при первом получении игроком в забеге (подбор, покупка). Усиленный/сигнатурный вариант открывается при первом получении именно в этом виде. Событие: уведомление игроку, немедленная запись в профиль, обновление списка слотов в книге приёмов.
6. **Открытие реликвии.** Реликвия открывается покупкой в хабе за самоцветы (цена по таблице: типично 6, редкие до 12) либо наградой за концовку. Подбор в забеге реликвию не открывает. Проклятые реликвии не открываются, они отдельный пул (шанс проклятия на выпадение 10%) и в хабе покупаются по отдельному предложению один раз за визит.
7. **Пул реликвий забега.** Формируется при начале забега и после каждой загрузки этажа: все открытые, плюс до 24 ещё не открытых (набираются по тирам, внутри тира порядок перемешан сидируемым RNG), минус: только-для-комбинирования, не-для-продажи, уже имеющиеся у любого игрока, реликвии из групп-исключений имеющихся. Реликвия, выпавшая в забеге, вычёркивается из пула до конца забега.
8. **Пул арканов забега.** Все арканы по тирам, кроме уже стоящих в слотах игроков. Не открытые собираются в список «новых» (не более 24 в сумме по тирам). При выпадении с вероятностью `1 − locked_rate` (из записи таблицы лута) сначала пробуется «новый»; если пусто — любой доступный. Шанс сигнатурного варианта — из записи таблицы. После пробы запись удаляется из обоих списков. Сильные арканы второй категории входят в пул лишь после флага «игра пройдена».
9. **Сохранение билда.** Выход из хаба сохраняет слоты, облик и назначенную реликвию игрока; следующий забег начинается с них. Билд проверяется на открытость: недоступное заменяется стартовым значением того же слота.
10. **История забегов.** Три слота лучших записей по режимам: стандартный, бесконечный (петля), на скорость. Запись: режим, петля, блок, этаж, время (текст и точное значение), до 12 реликвий, до 7 арканов с типом (обычный / усиленный / сигнатурный), облик и его улучшенность, флаги модификаторов (трудный, случайный билд, больше золота, кооп). Запись создаётся при победе; в режиме петли — и при смерти.
11. **Что считается лучше.** Стандартный и скоростной: меньшее время лучше. Бесконечный: сначала `петля × 100 + блок × 10 + этаж` (больше лучше), при равенстве меньшее время. Новый рекорд помечается флагом для показа «новый рекорд» один раз.
12. **Кооп.** Рекорд коопа берёт билд игрока, набравшего больше победных жетонов (при равенстве — случайно, но через сидируемый RNG).
13. **Сброс.** Полный сброс профиля обнуляет всё, включая историю, но оставляет настройки; требует двойного подтверждения и создаёт копию перед очисткой. Референс держит две копии и выбирает ту, где больше открытий; мы не выбираем по числу открытий — только по версии и контрольной сумме (иначе откат прогресса невозможно сделать намеренно).
