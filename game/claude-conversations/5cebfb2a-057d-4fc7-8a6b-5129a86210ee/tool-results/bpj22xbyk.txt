## 24-audio.md (11)

**A1 [ОШИБКА] §5 «≈1 с реального времени».** Кроссфейд и фейд-аут считаются по **масштабированному** `deltaTime`: на паузе (timeScale 0) они стоят, при замедлении (замирание при ударе) растягиваются. Скорость = (текущая громкость старого трека) в секунду и (целевая громкость нового) в секунду, т.е. ≈1 с игрового времени. Ожидающие переходы выполняются **все по очереди** в порядке запуска (не «последний побеждает»), каждый ждёт завершения предыдущего и окончания загрузки клипа. Закрыть открытый вопрос 4 спеки: в референсе — игровое время, на паузе стоит.
Источник: SoundManager.cs:BGMTransition.

**A2 [ОШИБКА] §10 пул голосов.** Признак «занят» ставится только голосам, привязанным к расстоянию/объекту (создаются записью дистанционного звука); обычные звуки **не помечают голос занятым**. Поэтому поиск «ближайшего свободного от индекса» учитывает только помеченные голоса; при полностью помеченных берётся следующий по кругу и обрывается (`Stop`). Простые звуки идут по кругу и перезаписывают любой голос. Индекс сбрасывается в 0 при загрузке сцены вместе с очисткой привязок. Защита от повтора 0.05 с считается по игровому времени (`Time.time`, масштабированному): в паузе звуки не играются, а при замедлении интервал растягивается.
Источник: SoundManager.cs:GetAudioSource, PlayAudio, AudioWithDistVar (availableAudioSources), ResetAllAudioSources.

**A3 [ПРОБЕЛ] §13 пересчёт громкости каждый кадр.** Раз в кадр громкость привязанного звука = (громкость клипа **или** переданная переопределённая) × доля расстояния, где доля считается с **максимальной дистанцией 24 м всегда** — пользовательская дальность и «процентная громкость» из первого вызова в пересчёте теряются (звук с иной дальностью после первого кадра меняет громкость). Начальная громкость учитывает дальность. Привязанный звук без цикла освобождается, когда клип перестал играть; зацикленный — когда исчез объект-источник (с остановкой). Позиция точно (0,0) = «глобальный» звук (доля 1).
Источник: SoundManager.cs:Update, GetPercentageVolume, PlayAudioWithDistance.

**A4 [УТОЧНЕНИЕ] §7 пауза SFX.** На паузе все играющие голоса ставятся на паузу и запоминаются; при снятии для каждого вызывается **Play()** (а не снятие паузы). Поведение «доиграть с места» не гарантировано (движок может начать клип сначала). Наш выбор: доигрывать с места (тест).
Источник: SoundManager.cs:TogglePause.

**A5 [ПРОБЕЛ] §7 правила паузы музыки.** (1) Меню паузы паузит музыку на открытии и снимает на закрытии. (2) Возврат из опций в меню паузы заново паузит музыку. (3) В опциях музыка снимается с паузы **только** на строке ползунка музыки и снова паузится при уходе на другую строку. (4) При возврате из опций на титуле музыка снимается с паузы. (5) Когда **все** игроки мертвы (до экрана итогов), музыка ставится на паузу и остаётся на ней до следующего запроса трека. (6) Любой запрос трека сначала снимает паузу музыки.
Источник: PauseMenuUI.cs:TogglePause, Update; OptionsMenu.cs:HandleValueUpdates; TitleScreen.cs; Player.cs (смерть всех игроков); SoundManager.cs:BGMTransition.

**A6 [УТОЧНЕНИЕ] §4 автозапуск.** Условие PvP проверяется по **точному имени** сцены «PvP»; сцена арены («PvPArena») в набор не входит — тишина. Сцены без трека (обучающая комната, эпилог, начальная загрузка) тоже тишина; сцена титров играет оригинальную аранжировку без суффикса и с громкостью оригинала независимо от настройки; запрос эпилога берёт титры в **текущей** аранжировке.
Источник: SoundManager.cs:AutoPlayBGM, PlayBGM, PlayEpilogueBGM.

**A7 [ПРОБЕЛ] §5 внутренности перехода.** (1) Сравнение с играющим: по имени клипа и признаку «играет»; совпадение — выход без перезапуска. (2) Имя вне набора: фейд-аут текущего (если есть) с той же скоростью и стоп; если ничего не играет — ничего не происходит. (3) Если клип не загрузился (пусто) — трек не стартует и очерёдность источников **не переключается**. (4) Старт при пустом проигрывателе — сразу целевая громкость, без фейда. (5) Загрузка клипа асинхронная: пока идёт загрузка, любые переходы ждут. (6) Громкость после фейда выставляется точно, старый источник обнуляется и останавливается.
Источник: SoundManager.cs:BGMTransition, InitBGMSettings.

**A8 [ОШИБКА] §8 «внешние клипы из пользовательской папки подхватываются при старте».** В референсе механизм не запускается: список имён пуст, метод загрузки никем не вызывается. Загрузчик (если включить) читает `<папка данных>/Sounds/<имя>.wav`, громкость по умолчанию 0.25, шина «игра». Для среза: не реализовывать.
Источник: SoundManager.cs:LoadFromExternalFolder, LoadAllExternalSoundFiles, LoadExternalSoundFile (внешний список пуст, вызовов нет).

**A9 [УТОЧНЕНИЕ] §11 звуки меню.** Открытие/закрытие/подтверждение/ошибка идут с флагом «игнорировать интервал»; **звука отмены нет** (пустая функция). Звук «шаг меню» в большинстве меню с флагом, в меню снаряжения/инвентаря — без флага (подчиняется интервалу 0.05 с). Подтверждение = клип «снаряжение».
Источник: SoundManager.cs:PlayMenuAudio, PlayConfirmAudio, PlayErrorAudio, PlayCancelAudio; EquipMenu.cs; InventoryMenu.cs.

**A10 [ПРОБЕЛ] прочее.** Начальный снапшот микшера «по умолчанию» применяется мгновенно; все 50 голосов при создании назначены на шину UI, шина проставляется заново при каждом проигрывании; параметры громкости микшера — по одному на шину музыки и SFX; модификатор общей громкости клипов = 1. **A11 [ПРОБЕЛ] классы без покрытия.** Тестовые/отладочные (в игре не участвуют): тест звуков смерти (чередует анимации, при игроке ближе 8 м запускает «замирание с выходом» времени), тест звукового дизайна (сброс данных профиля, открытие всех арканов, перезарядка 0.25 с, смертельная защита), тестер нормализации громкости (проигрывание по флагу).

## 25-ui-hud.md (30)

### HUD игрока

**U1 [ОШИБКА] §1 «след урона держится 1.5 с, затем сходится».** Таймер 1.5 с **не удерживает** след. Логика: при падении HP, если предыдущий таймер уже истёк (или не был запущен), след переустанавливается на HP до удара; таймер перезапускается на 1.5 с, но больше нигде не читается. След убывает **каждый кадр сразу** со скоростью 25 HP/с, пока он выше текущего HP (время масштабированное). Т.е. нет паузы-удержания; вторая рана в окне 1.5 с продолжает текущий след без переустановки. Для полосок врагов-боссов то же с таймером 0.4 с и скоростью из префаба (скорость в данных не найдена).
Источник: PlayerStatusBar.cs:HandleHealth; EnemyHealthBar.cs:HandleHealth.

**U2 [УТОЧНЕНИЕ] §1 мигание тревоги.** Параметр «циклов/с» — на деле полуциклов: значение лерпа 0↔1 растёт со скоростью max(0.3 − доля, 0.1) × 22 за секунду (2.2 при доле ≥ 0.2, до 6.6 у нуля); полный цикл белый→красный→белый = 2/скорость. Фон и портрет красятся одним цветом. Звук тревоги не играет на экране загрузки; текст HP — усечение до целого, «текущее/максимум (с модификаторами)».
Источник: PlayerStatusBar.cs:HandleHealth.

**U3 [УТОЧНЕНИЕ] §1 «второй набор сдвинут ≈ 366 px».** Сдвиг +366 px — у всех элементов панели здоровья; **панель реликвий второго игрока сдвинута на +264 px**, и её 12 иконок идут в обратном порядке (заполнение справа налево: индекс 11→0). Цвет портрета берётся из палитры облика игрока (индекс палитры на экземпляре материала).
Источник: PlayerStatusBar.cs:Claim, ClaimPlayerStatusBar; ItemStatusBar.cs:ItemWindow.Initialize.

**U4 [ПРОБЕЛ] §5 панель реликвий.** 12 слотов; порядок = порядок вставки в словарь; цвета: Disabled — иконка (0.4,0.4,0.4,0.7), Ready — (1,1,1,0.8), Active — иконка (1,1,1,0.8) + подложка (208,247,255,102) и рамка (219,249,255,115); обычная рамка (109,109,109,80), подложка (0,0,0,0.31). Новая реликвия добавляется в состоянии Disabled; **звук при каждой смене состояния**: Active — «активация», Ready — «готов», Disabled — «деактивация» (UI-шина); удаление перестраивает ряд.
Источник: ItemStatusBar.cs:ItemWindow.UpdateItem, Rearrange, ItemObj.SetObjVars.

**U5 [ПРОБЕЛ] §4 запасной (седьмой) слот и кнопка карты.** Иконка клавиши запасного слота — кнопка «меню снаряжения» (по схеме ввода игрока). Рядом **плитка «карта»**: иконка кнопки «карта»; активна (рамка (160,160,160,255), иконка/текст (1,1,1,0.6)) только в игровой сцене и не в сцене босса; иначе затемнена ((0.4,0.4,0.4,0.6), оверлей включён). Фон запасного слота: фирменный/усиленный/обычный по аркане (индексы 4/2/0).
Источник: StockSkillUI.cs:RefreshUI, Update, ToggleMap, Activate; CooldownUI.cs:GetKeySpriteFromSkillSlot.

**U6 [УТОЧНЕНИЕ] §4 текст кулдауна и пинг.** Формат: `<10 с` — «0.0» (округление, не усечение: 9.96 → «10.0»), `>=10` — «0» (10.4 → «10», 12.6 → «13»). Пинг готовности запрашивается и при переходе Cooldown→**NotReady** (если по окончании КД аркана заблокирована по условию), и при Cooldown→Ready; первый пинг возможен через 0.5 с после привязки HUD к игроку (таймер стартует в Claim). Для арканы с зарядами: при готовом заряде текст = число зарядов, оверлей зависит от «готов ли можно использовать»; иначе текст = остаток (задержки между зарядами или перезарядки) с тем же форматом, заливка оверлея = остаток / (время задержки или полное время). Заливка рамки = доля суммарных зарядов. У отключённого слота иконка-заглушка и скрыта иконка клавиши. Окно пинга одно на игрока (0.5 с).
Источник: CooldownEntry.cs:EntryUpdate, SetChargeCooldown, SetCooldown, SetNotReady, SetReady, Disable; CooldownUI.cs:Claim, RequestCDPing.

**U7 [ПРОБЕЛ] §7 каст-бар.** Два режима: «заряд» — заливка 0→1 цветом (0,0.6,1,0.8), при 100 % меняется на зелёный и держится до `EndCast`; «разряд» — заливка 1→0, по завершении гасится. Не создаётся при скрытом интерфейсе; прерывание — флаг принудительного выхода (гасит на следующем кадре); сбрасывается при деактивации. Якоря 0.44–0.56 × 0.7–0.71 — размеры внутри рамки бара. Бар следует позиции родителя каждый кадр; при пропавшем родителе уничтожается (если не помечен «сохранять»).
Источник: CastBar.cs:StartCast, EndCast, CastBarStart; MiniUIBar.cs:LateUpdate; PlayerHUD.cs:Start.

**U8 [ПРОБЕЛ] полоска щита и пинги.** Полоска щита привязана к позиции хёртбокса игрока, видна при щите > 0 (заливка = доля щита). Два вида пинга: «пинг арканы» (иконка арканы) и «пинг предмета» (иконка реликвии) — анимации перезапускаются с начала. Подсказка воскрешения у умершего: иконка кнопки подтверждения (геймпад — зелёная, клавиатура — «пробел», зашито).
Источник: PlayerHUD.cs:HandleShieldBar, MiscPing, CooldownPing, Start.

### Полоски врагов, счётчик

**U9 [УТОЧНЕНИЕ] §12 полоски врагов.** Два разных вида: (а) **мини-полоска над головой** (по реликвии «полоски»): цвет (0.6,0,0,0.8), размер 0.44–0.56 × 0.45–0.46 в рамке; показывается для обычных врагов, вошедших в зону-активатор (не для мини-боссов, боссов, тренировочной куклы); пул 25; активатор включается только на этажах и заново включается через кадр после загрузки сцены; (б) **полоска босса/мини-босса**: имя, заливка, след (U1), щит; появляется всегда; fade-in прозрачности 0.01→1 за 0.25 с и «налив» заливки 0→полная за 1 с.
Источник: EnemyHPBarActivator.cs:OnTriggerEnter2D; EnemyHPBars.cs; HealthBar.cs; EnemyHealthBar.cs:FadeIn, HandleFillIn; Boss.cs; MiniBoss.cs.

**U10 [ОШИБКА] §8 счётчик черепов.** Заливка активного черепа **убывает** от 1 к 0: `1 − (прогресс между порогами)` (для первого: `1 − доля/0.3`); при достижении порога гасится **самый старший из горящих** (индекс 2, затем 1, затем 0) по анимации; за кадр не более одного; кадр после генерации этажа пропускается. Состояние гашения зеркально (в обратном порядке) пересылается в алтарь и круг активации особой комнаты. Скрыт вне этажей; при смене сцены сброс.
Источник: EnemyCounterBar.cs:Update, Reset, OnSceneLoaded; MiniBossAltar.cs; MiniBossActivationCircle.cs.

### Объявления

**U11 [ПРОБЕЛ] §10 механика объявлений.** Название этапа: показывается после загрузки через 0.2 с, шрифт 60, длительность удержания 0, подчёркивание есть. «Бой»: шрифт 180, красный, скорость анимации 1.75, толстая линия (масштаб Y 5). «Победа»: шрифт 120, цвет (0.93,0.85,0.4), кайма (0.6,0.41,0.2), старт анимации с кадра 0.5, удержание 1 с, конфетти 24 в центре + по 8 слева/справа со сдвигом ±2.5 м. «Комбо»: «N» + текст, красный, шрифт 60, 0.75 с. Алгоритм: анимация «появление» играет до 30 % времени, затем удерживается кадр 0.55, пока не истечёт длительность; новое объявление при идущем отменяет текущее (пауза 3 кадра). Шрифты >= 90 × множитель языка сдвигают подчёркивание вниз на 20 × размер / (90 × множитель) (корейский 24 вместо 20). Строка-уведомление: по умолчанию 3 с; при гонке боссов, если другого уведомления нет, каждые 0.5 с показывает общее время (целые секунды).
Источник: StageTitleUI.cs:Announce, Announcement, AnnounceVictory, AnnounceCombo, AnnounceFight; GameUI.cs:Update, BroadcastNoticeMessage; LoadingScreen.cs:AnnounceStage; TextManager.cs:SetAnnounceLineSpacing.

### Пауза, подтверждение, меню снаряжения

**U12 [ПРОБЕЛ] §13 детали паузы.** Подтверждение в меню паузы принимается кнопкой «Подтверждение» **или** клавишей пробел (зашито). Меню паузы закрывается по **отпусканию** кнопки «Меню» или «Отмена» (открывается по нажатию «Меню»). Пауза запрещена: при всех мёртвых, активном итоге этажа, на экране загрузки (отложенная пауза выставляется после загрузки), в сцене титров; клавиша «Меню» не открывает паузу у клавиатурного игрока в состоянии «Paused» (меню снаряжения/хаб-окно открыто). Отключение устройства основного контроллера ставит паузу в очередь, если меню паузы не открыто. Экран загрузки принудительно закрывает меню паузы. Размытие — включение компонента на камере.
Источник: PauseMenuUI.cs:HandleConfirmInput, Update, TogglePause; GameController.cs:Update (pauseQueued, loadingPauseQueued); InputController.cs:OnControllerDisconnected; LoadingScreen.cs:Update.

**U13 [ОШИБКА] §15 меню снаряжения.** (1) Открытие переводит **только игрока** в состояние «Paused» (мир идёт); закрытие — обратно в Idle. Доступно из Idle/Run (и открытое остаётся при переходе в Paused). (2) Закрытие: повторное нажатие «меню снаряжения», отпускание «Отмена», потеря доступности, быстрая замена (закрывается следующим кадром), блокировка на паузе игры. (3) «Значимые» арканы (нельзя оставить слот пустым/заменить): базовая атака, фирменная, рывок. Запасной слот не принимает базовую/фирменную/рывок (ошибка). (4) Быстрая замена: удерживать «меню снаряжения» + нажать слот — меняется со запасным; значимый → звук ошибки. (5) Навигация: порог стика 0.3 нажатие / 0.2 отпускание; «лево/право» по 6 слотам с заворотом mod 6; «вниз» из слотов — на запасной (если он есть), иначе в решётку реликвий; «вверх» — на панель облика; с панели облика «вниз» возвращает. (6) Рамка выбора пульсирует альфа 1↔0.6 со скоростью 1/с. (7) Инфо-панель: `[<золотой #FFCC00>имя</золотой>]` + описание (для арканы с усилением — блок «усиление», 27); флаги арканы (до 5 значков), для реликвий — значок категории (атака/защита/разное). Звуки: открытие/закрытие, «шаг», «снаряжение» при выборе/обмене, «ошибка» при запрете.
Источник: LowerHUD.cs:HandleEquipMenu, SetEquipMenuStatus; EquipMenu.cs:Update, HandleQuickSwap, HandleNavigation, IsSignificantSkill, SelectSlot, LoadEquipMenu, ExitMenu; OutfitMenu.cs.

**U14 [ПРОБЕЛ] §15 решётка реликвий.** Раскладка: 6 колонок × 2 ряда видимо (якоря: ширина 0.115, отступ слева 0.03, шаг 0.05; высота 0.32, начальный отступ 0.1, шаг 0.12), до 30 предметов. Навигация по рядам с заворотом влево на последнюю клетку ряда (но не за число предметов); «вниз» с последнего ряда — на последнюю клетку; «вверх» из первого ряда возвращает в слоты (индекс колонки переносится, колонка % 6). Инфо: имя, метка «проклятая» красным, для групповых предметов — прогресс «1/N» или строка комплектации, затем описание с динамической добавкой. «Взаимодействие» выбрасывает, после чего выбор смещается на предыдущую клетку; при пустом списке фокус уходит в слоты. «Подтверждение» на головном уборе надевает его.
Источник: InventoryMenu.cs:LoadMenu, HandleNavigation, SelectItem, HandleDropItem, HandleItemHeadgear, SetFocus.

**U15 [ОШИБКА] §16 очередь уведомлений «до 20».** 20 — только начальная ёмкость очереди, **предела нет**. Дубликат определяется только по имени среди ожидающих (текущий показываемый не учитывается). Следующее уведомление начинается, когда текущая анимация проиграна на 80 %. Позиция: над игроком +2.75 м. Потеря арканы — анимация и звук «потеря арканы», потеря реликвии — звук «потеря реликвии».
Источник: NewItemNoticeUI.cs:Display, ShowDisplay, LateUpdate.

**U16 [ПРОБЕЛ] уведомление о разблокировке.** Отдельная очередь (ёмкость 20 — не предел), 4 типа: аркана, фирменная, реликвия, облик (палитра облика); заголовок = имя + текст «разблокировано», подзаголовок по типу; показ: анимация «появление», удержание 1.5 с после 75 % проигрывания, затем «скрытие»; звук «вступление» только если очередь пуста и ничего не показывается, звук «выход» при каждом показе; очередь и анимация сбрасываются при загрузке уровня.

### Хаб-окна

**U17 [ОШИБКА] §20 «в соло — центр 50%», §18, §19.** Все хаб-панели (книга, гардероб, сундук реликвий, лодаут, магазин-окно арканов) для игрока 0 занимают **левую половину** экрана (якорь 0..0.5 по X), для игрока 1 — правую (0.5..1); в соло панель тоже слева (центральный вариант 0.25–0.75 в коде объявлен, но не вызывается). Лодаут второго игрока зеркалится. Открытие любой панели переводит игрока в состояние «Paused»; панели выезжают за экран: смещение скрытия 300 px по X (к ближнему краю: влево, для правой половины — вправо) или 600 px по Y; в одной группе (на игрока) одновременно идёт только одна анимация перехода (блокировка по ID группы).

**U18 [ОШИБКА] §18 лодаут-стенд.** Вместо «6 реликвий» в слоте лодаута: **один облик, одна стартовая реликва, 4 аркана** (базовая, рывок, обычная, фирменная); 6 слотов на каждого игрока отдельно. Управление: вверх/вниз с заворотом 0..5, задержка первого повтора 0.4 с, дальше автоповтор 0.2 с; «Подтверждение» → запрос загрузки, «Взаимодействие» → запрос сохранения (в окне подтверждения по умолчанию выбрано «нет»; сохранение в PvP запрещено со звуком ошибки). **Загрузка**: если облик занят другим игроком — остаётся текущий; снаряжается облик; профиль сохраняется; инвентарь очищается (проклятые сохраняются); стартовая реликва выдаётся (не в PvP); 6 слотов арканов очищаются и 4 аркана ставятся **на те же индексы слотов**, где были базовая/рывок/обычная/фирменная; фирменной ставится флаг; HP восстанавливается до полного. **Сохранение**: текущий облик, стартовая реликва и 4 аркана; звук затвора; профиль переменных сохраняется при закрытии, если были изменения. Листание страниц: задержка автоповтора 0.25 с / 0.125 с (не только в сундуке); звук «шуршание страницы» при смене страниц.

Источник: Wallet.cs:Deposit; PlatWallet.cs; GameData.cs:PushPlatinumBalance, ResetPlatinumBalance.

**S5 [ПРОБЕЛ] §5 правила числовых счётчиков.** Чтение отсутствующего счётчика даёт **−1** (не 0); инициализируются все 8 ключей нулями. Увеличение — только в игровых сценах и на ≥ 1 (предел 99 999 999). Счётчик убитых по типу растёт **без** ограничения сценой (в любой сцене, где враг умер). Использование арканы: не учитывается в комнате игрока, хабе, PvP (сцена содержит «PvP»); у арканы растёт `useCount`, при ульте — ещё и `overdriveCount` на тот же инкремент; суммарно по стихии растёт тот же инкремент; учитывается только инкремент > 0. Время игры: накопитель времени с последнего сохранения прибавляется к общему при записи профиля и обнуляется. Запись данных (UpdateData) обновляет: время, флаги арканы/подписи (только поднимает флаги, не снимает), облики, баланс кристаллов (и проверка достижения).
Источник: GameData.cs:GameStats.UpdateIntStatValue, GetIntStatValue, EnemyDefeated, UpdatePlayTime; UpdateSkillDataEntry, UpdateData, PushSkillData; Enemy.cs (учёт убитых); Player.cs (смерть, падение).

**S6 [ПРОБЕЛ] §7 начальные значения профиля.** Словарь NPC начинается с одного флага «истина» (особый NPC-подопечный, ID в Источнике); обучение не пройдено; хаос-приёмы недоступны; облики: открыты два стартовых; профиль — 2 слота данных игрока (по числу игроков).

**S7 [ПРОБЕЛ] §9 когда пишется журнал.** Запись формируется **только при входе в сцену концовки** (победа), не при смерти. В коопе запись содержит билд **победителя** (при ничьей/без данных — игрока 0). Состав: режим (скоростной = гонка боссов; бесконечный = петля > 0; иначе стандартный), петли, этап, этаж, время текстом и числом (строка), 12 реликвий (порядок инвентаря), 7 арканов (6 + запасной; типы 0 обычная / 1 усиленная / 2 фирменная; у запасной только 0/1), облик + «улучшен», флаги: петля, скорость, трудный, лишнее золото (не в гонке боссов и если обмен у ювелира был), случайный, блокировка этажа, особый хард, кооп. Сравнение: стандарт/скорость — меньшее время; бесконечный — 100×петли + 10×этап + этаж, при равенстве меньшее время. «Новая запись» метка — флаг по режиму до закрытия экрана.
Источник: RunHistoryEntry.cs:Save, IsBetterRun; GameController.cs:LoadLevel (Ending); RunHistoryUI.cs (newRecordFlags).

Экран: три записи по режимам; стадия показывается как `петли × (число базовых стихий) + этап + 1` «-» `этаж`; корона кооп-записи не в скоростном режиме; фейд появления 0.18 с; цвета подложек реликвий (обычные без фона, проклятые красноватая подложка (0.51,0.11,0.11,0.3) с контуром (0.184,0.114,0.114)); арканы с выключенной подложкой (0.8,…). **Сброс истории**: «Взаимодействие» → три подряд окна подтверждения (заголовки 1/2/3) → очистка всех трёх записей, сохранение, обновление стеллажа; закрывается при удалении игрока дальше 4 м или паузе; игрок на время подтверждения в состоянии «Paused».
