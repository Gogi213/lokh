# 08. Расстановка врагов

## Цель

Плотность боя в комнате определяется формулой, а не ручной расстановкой: чем больше пол, тем больше «стоимости» врагов, но состав собран из готовых групп, поэтому комната читается (ядро в центре, мелочь по краям). Одна комната из трёх — «выживание»: двери запираются, враги идут волнами. В конце этапа — добровольный бой с элитой. Срез: любая сгенерированная комната (07) получает врагов по бюджету; плотность проверяется симуляцией.

Отличия от референса (одной строкой): все константы (шансы, коэффициенты, цены, веса) — в `data/encounters.json`, не в коде; вес добавки — явная колонка, а не усечённая разность; пул «выживания» содержит только волновые группы (в референсе в нём лежат и обычные, из-за чего реальная доля выживания ниже 35%); первая волна стартует с общей задержкой, а не с перекосом «первый враг позже остальных».

## Поведение

### Бюджет комнаты

`B = число_клеток_пола × k`, где `k = 0.08` (кооп — `0.125`). Считаются только клетки с полом (ямы и стены не в счёте). Для 16×12 с ~150 клетками пола: `B = 12`.

### Цены врагов

|Враг|Цена|Враг|Цена|
|---|---|---|---|
|Слизень|0.5|Мечник|2|
|Плеватель, катыш|0.75|Копейщик|2.5|
|Гуль, зональный|1|Лучник, маг|3|
|Турель, орбы|2|Разбойник, призыватель, любой стихийный|4|
|Большой гуль, гроб, страж|4| | |

Цена группы — сумма цен. Элита и миньоны в бюджет не входят.

### Алгоритм «ядро + добавки»

1. **Выбор режима.** С шансом **0.35** комната «выживание» (берётся пул выживания), иначе обычный пул ядер.
2. **Выбор ядра.** Из трёх размеров рамок (4×4, 6×6, 8×8) остаются те, что физически помещаются в комнату (все клетки рамки — пол, отступ от краёв: 4 клетки сверху/снизу, 2 слева/справа). Размер выбирается с весом = числу групп в этом размере; затем группа — равновероятно.
3. **Стоимость.** Ядро всегда ставится, даже если дороже бюджета (комната не пустеет); его цена идёт в «потрачено».
4. **Добавки** (если ядро их допускает):
   - обычная комната: `n = int(clamp(B / (потрачено + 1), 0, 2))`;
   - выживание: `n = random(0..2)`, в коопе `random(1..4)`;
   - нет ядра, но влезают добавки: `n = 4`, комната «выживание» с шансом 0.5.
   Цикл по `n`: с шансом 0.2 остановиться (не при первой добавке без ядра); выбрать добавку по весу; если `B − потрачено − цена < 0` — **остановиться совсем**; иначе добавить и учесть цену.
5. **Веса добавок:** слизень 4, гуль 4, зональный 4, мечник 3, копейщик 2, лучник 2, маг 2, разбойник 1, призыватель 1, стихийный 1. Нет ядра и нет добавок — комната пуста.
6. **Подмена на стихийных.** Если этап стихийный: каждый член ядра, имеющий стихийный аналог (мечник, лучник, маг, разбойник, копейщик, призыватель; слизень → плеватель/катыш/зональный; турель → зональный), заменяется им с шансом **0.55**. В пул добавок входят все варианты текущей стихии и зональный этой стихии. После подмены вычеркнуть группы с врагом чужой стихии.

### Размещение

- Ядро — в центре комнаты, если рамка там помещается, иначе в случайной допустимой клетке. Первые `centerCount` (0–4) врагов ядра стоят в центре: 1 — в точке, 2 — слева/справа на ¼ ширины рамки, 3–4 — по окружности радиусом 20% рамки. Остальные (добавки ядра) — по углам/краям рамки, 4 попытки на каждого без совпадения клеток.
- Добавки без ядра: случайные точки внутри рамки 4×4, минимум 0.25 м друг от друга, 4 попытки.
- Враги появляются «спящими» (в `IDLE`, не в тревоге); внутри комнаты — тревога по правилам 06.

### Группы-ядра (центр. — число врагов в центре)

Обозначения: М мечник, Л лучник, Мг маг, Р разбойник, К копейщик, П призыватель, Сл слизень, Г гуль, БГ большой гуль, Гр гроб, Ст страж, Т турель.

**4×4 (15):** центр 1 — БГ; Гр; Ст; Мг+М; Л+Р; Т+2Г; К+2Г. Центр 2 — М+Р; 2Мг; 2Л; Л+К; 2Р. Центр 4 — 4Сл. Центр 3 — 3Г; 3М.

**6×6 (16):** центр 1 — БГ+2Г; П+2Г; Л+2М; К+2М; Р+2М; Мг+2М. Центр 2 — 2Гр; 2К; Гр+К; Л+Р+2Г; 2Мг+2Г. Центр 3 — 3М+2Г; Гр+2Мг; Ст+2Т; 3Т.

**8×8 (10, без добавок):** центр 1 — Ст+П+2Г; Ст+К+2Г. Центр 2 — 2БГ+4Г; 2Л+2М; 2П; 2Мг+2М. Центр 3 — 6Г; П+2Гр; К+2Гр. Центр 4 — Л+Мг+М+Р.

**Выживание 4×4:** обычные (без волн) — {М, К, Мг, Л, Р}+2Г; волновые — 4Сл; 2Сл+2Г; 3Г; 2М; 2К; 2Мг; 2Л; 2Р; П+2Г; БГ+2Г. **6×6 (волновые):** 2Г+Т+2М+Л; 3Г+2Р; 2Г+Р+2М+К; 4Г+3М; 2Г+3БГ; 2Мг+2П; 2Мг+2Л; 2Сл+2Т+2Г+Л; 2П+2Г+2М+П (последние 2 группы допускают добавки); 5Сл+Гр+3Г. **8×8:** 2Г+Т+2М+Мг+2Р+Л; 2Т+2Мг+2П; 3Г+3М+2К; М+2Г+3БГ+2Гр+Ст; 2Сл+2Г+2Гр+2Г+2К+2Г.

### Комнаты выживания

- Группа делится на **волны** по `N` врагов: `N = centerCount`, если он > 0, иначе 4; если остаток после деления на 4 равен 1 — волна одна на всех (без одиночки в хвосте). Добавки группы — не волны: стоят в комнате с начала.
- Игрок заходит во внутреннюю часть комнаты (размер комнаты −2 по обеим осям) → **двери запираются**, звук блокировки, точка возрождения = место входа; в коопе остальных игроков телепортируют к вошедшему.
- Враги волны появляются из порталов в случайных допустимых клетках (минимум 2 клетки от центра, разные клетки), сразу «в тревоге» с радиусами 999 (преследуют всегда). **Каденс:** враг № `j` волны появляется через `j × 0.125 с` после старта волны; к первой волне общая задержка 1.0 с. Следующая волна стартует в тот же кадр, когда **убит последний** враг предыдущей.
- Последняя волна зачищена → двери открываются, эффект победы; с шансом **0.25** — малый сундук в центре.
- Все игроки мертвы → комната сбрасывается: непогибшие враги удаляются без добычи, прогресс волн обнуляется, двери открываются, триггер взводится заново.

### Режим «двойные враги»

Включается предметом. Каждый поставленный враг получает копию в случайной точке круга радиусом 1.5 м; в коопе — две копии. Волны выживания: каждый портал спавнит за **2 цикла** (кооп — 3) с интервалом 0.25 с в квадрате 1.5×1.5. Общее число врагов этапа (для счётчика) увеличивается соответственно. При «двойных» генератор этажа всегда выбирает комнату случайно из всего пула (обычно — с шансом 0.3); см. 07.

### Кооп

Бюджет `k = 0.125` (×1.5625); добавки в выживании `1..4` вместо `0..2`; «двойные» — 3 врага вместо 2; циклы выживания 3 вместо 2; щит финального босса ×2 (300 → 600); цель босса — случайный живой игрок.

### Элита

Элита не ставится в комнатах. Это **добровольный бой в конце этапа**: у выхода стоит алтарь с тремя черепами, шкала — доля убитых врагов этапа (`убито / всего`). Черепа гаснут на 30%, 60% и 90%. Игрок активирует алтарь → `u = 1 − доля` (не убитое):

- Тип элиты: список из 7 групп (мечник, копейщик, маг, призыватель, разбойник, лучник, гроб); индекс следующей = `(прошлый + random(1..6)) mod 7` — **два раза подряд один тип не выпадает** (счётчик живёт весь забег).
- Группа: элита + 2 одноклассника + 3 гуля (у мечника: мечник, копейщик, 3 Г; у гроба: гроб, БГ, 3 Г). **Добавок: `5` при `u > 0.7`, `4` при `u > 0.4`, `3` при `u > 0.1`, `2` иначе** — берутся с начала списка (сперва одноклассники, потом гули), порядок перемешан.
- Подмена на стихийных: шанс `0.5 × u` для каждой добавки.
- Появление: элита в центре через 1.5 с, добавки по кругу радиусом 6 м с задержкой `1.5 + random(0.1; 0.5)` с; добавки без добычи и без вклада в статистику. Награда — сундук элиты (09).

## Критерии приёмки

**Headless (симуляция 1000 комнат на сид):**
1. Для 16×12 с 150 клетками пола: средняя «потраченная» стоимость в обычных комнатах — не больше `B + 0.5×цена ядра` и не меньше `0.5·B`.
2. Доля комнат-выживания среди комнат, где ядро выбрано, = 0.35 ± 0.03; ни одного волнового ядра в обычной комнате и ни одной не-волновой группы в пуле выживания.
3. Добавок в обычной комнате ≤ 2; в выживании ≤ 2 (кооп ≤ 4).
4. Выживание: враг № `j` волны возникает на `j × 0.125 с` (±1 тик); следующая волна — на том же тике, что и смерть последнего; смерть всех игроков сбрасывает комнату.
5. Подмена: на стихийном этапе 55% ± 5% подходящих врагов становятся стихийными; чужой стихии нет.
6. Режим «двойные»: каждый поставленный враг даёт 2 экземпляра (кооп 3); кооп-бюджет ×1.5625.
7. Элита: 1000 боёв — число добавок соответствует таблице по `u`; два подряд одинаковых типа = 0.
8. Один сид = один хеш расстановки.

**Визуально (скриншот):** комната с ядром в центре и добавками по краям; запертая комната выживания с дверями и порталами; алтарь с тремя черепами и гаснущей шкалой.

## Открытые вопросы

1. Вес добавок при дробной цене (2.5) — усечение даёт 2; задать явной колонкой — подтвердить значения.
2. Нужно ли сохранять перекос стартовой задержки (первый враг волны на 1.0 с, остальные раньше)? Принято решение: общая задержка.
3. Как считать долю убитых при «двойных» и выживании: по `убито / всего` с учётом копий (принято так).
4. Какие комнаты получают врагов вообще (флаг «случайные враги») — решается в 07.
5. Размер сундука элиты и шансы наград — 09.

# 09 — Лут, валюты, магазины

## Цель

Убийства и сундуки дают золото, кристаллы, сердца, реликвии и арканы по таблице данных; награда незаметно подстраивается под ход забега; магазины показывают честный выбор без повторов. Игрок не видит переключателей, но чувствует «справедливость»: потратил всё — дальше щедрее, лежит на золоте — скупее, на грани смерти — сердца падают чаще.

Отличия от референса (по одной строке):
- Референс бросает глобальный рандом — у нас каждый дроп считается из потока `hash(floor_seed, source_id, drop_index)`: тот же сид + те же убийства = тот же лут, лишний бросок где-то ещё его не сдвигает.
- Пул реликвий в референсе при пустом списке молча ничего не даёт (и 10% выпавшего «проклятого» броска пропадает) — у нас запасной пул.
- Поле «шанс заблокированной арканы» в референсе перевёрнуто (1 = не искать новую) — у нас поле `prefer_new_spell` читается прямо.
- Цены, тиры, группы исключений и константы лежат в данных (`data/loot.json`, `data/prices.json`, `data/relics.json`), не в коде.

## Поведение

### 1. Валюты

| Валюта | Живёт | Назначение | Предел |
|---|---|---|---|
| Золото | один забег (счётчик «собрано на этаже» сбрасывается каждый этаж) | магазины забега | нет |
| Кристаллы | между забегами | разблокировка реликвий и арканов в хабе; проклятая сделка | 999 |
| Сердца | подбираемое | лечение (величина подбора — в 01/02) | — |
| Души | только кооп, пока партнёр мёртв | оживление партнёра | — |

Золото падает монетами 1/5/10: пока остаток >0, монета выбирается равновероятно из {1}, {1 или 5, если остаток ≥5}, {1, 5 или 10 по остатку}.

### 2. Схема строки таблицы дропа

Одна строка на источник (класс врага, тип сундука, разрушаемый предмет). Все поля, кроме имени, необязательны.

| Поле | По умолчанию | Смысл |
|---|---|---|
| `gold_rate` | 1 | шанс, что золото вообще выпадет |
| `gold_min`, `gold_max` | 0 | равномерное целое включительно |
| `gold_compensate` | true | применять подстройку (§4) |
| `crystal_rate`, `crystal_min`, `crystal_max` | 0 | см. §3 |
| `heart_rate`, `heart_min`, `heart_max` | 0 | число бросков §3 |
| `relic_rate`, `relic_min`, `relic_max` | 0 | число бросков |
| `spell_rate`, `spell_min`, `spell_max` | 0 | число бросков |
| `prefer_new_spell` | 1 | шанс сначала искать ещё не открытую аркану |
| `signature_rate` | 0 | шанс дать улучшенную версию аркана вместо новой |
| `soul_min`, `soul_max` | 0 | души (кооп) |
| `spell_list`, `relic_list` | пусто | сценарный дроп: выбор из списка |

Нормализация при загрузке: `max`=0 при `min`>0 → `max`=`min`; для кристаллов, сердец, реликвий, арканов при `rate`>0 и `min`=0 → `max`=1.

### 3. Расчёт количества

- **Золото.** С шансом `gold_rate`: целое из [min, max] × глобальный множитель (кооп +10%) × подстройка (если включена) → округление вверх. Золото без подстройки добавляется в счётчик `uncompensated`.
- **Кристаллы.** База = `crystal_min` (гарантия). С шансом `crystal_rate` база заменяется равномерным целым из [max(min,1), max]. Затем множитель этапа M = min(0.25 × сложность, 1), где сложность = круг×3 + номер этапа (0–2) + стартовая. Если количество >1 → floor(n × (1+M)); если =1 → 1 + плоский бонус + (1 с шансом M).
- **Сердца.** `heart_min` гарантированных + по одному броску на каждую единицу от min до max с шансом `heart_rate` × подстройка здоровья (§4).
- **Реликвии и арканы.** `min` гарантированных + по броску на каждую единицу до max с шансом `rate`. Число реликвий умножается на глобальный модификатор (1.0) с отбрасыванием дроби.

### 4. Подстройка наград

**Золото.** Работает, только когда побеждено ≥50% врагов этажа, иначе множитель 1. Пусть d = 1 − (золото_этажа − uncompensated) × 0.005. Если d ≥ 0: множитель = 1 + 0.5·d; иначе = 1 − 0.5·min(1, −d). Примеры: собрано 0 → ×1.5; 100 → ×1.25; 200 → ×1.0; 300 → ×0.75; ≥400 → ×0.5.

**Здоровье.** Берётся наименьшая доля здоровья среди живых игроков h; множитель шанса сердца = линейно от 1.75 (h=0) до 0.5 (h=1): 1.75 − 1.25·h. Гарантированные сердца множитель не трогает.

Целые значения вроде «5 гарант.» — гарантия базой; множитель этапа увеличивает: 5 → 5/6/7/8/10 по кругу, 20 → 20/25/30/35/40.

### 6. Реликвии: пул без возврата

Пул строится при каждой загрузке этапа заново (не раз на забег): из полного списка убираются стартовый, «победный», сборные (только по рецепту), нерозничные, уже имеющиеся у любого игрока, их исключения (§7) и компоненты уже собранных групповых реликвий.

Разблокировка: в пул входят открытые реликвии плюс до `locked_cap` (24) ещё не открытых, набранных по тирам от нижнего вверх (внутри тира случайно) — игрок видит новое, но не всё сразу. Тир 0–4 влияет на цену разблокировки, не на шанс выпадения; шанс равномерный.

Выбор: бросок против `curse_chance` (0.1 по умолчанию, одинаково для дропа и сундуков) → проклятый пул, иначе обычный; элемент берётся равновероятно и вычёркивается. Предел инвентаря — 12 реликвий, 12 проклятых.

Проклятый пул отдельно: проклятые реликвии минус нерозничные и только-хабовые. Особый «хаб-пул» проклятых служит сделке в хабе.

Отличие: референс при пустом выбранном пуле ничего не выдаёт; у нас пустой пул → запасной (другой пул), и только если оба пусты — нет дропа.

### 7. Группы исключений

- **Вытеснение:** владение реликвией A убирает из пула список B(A) (составная реликвия вытесняет свои части; сет вытесняет компоненты; комбинированная стихийная — обе родительские).
- **Взаимоисключение:** в каждом множестве можно держать только одну; поднятие второй сбрасывает остальные; если среди имеющихся есть проклятая — подъём отклоняется.
- **Группа:** в инвентаре компоненты группы считаются одним предметом; их по отдельности в пул не возвращают.
- **Сборная:** выдаётся только как недостающая часть рецепта.

### 8. Цены и тиры

Базовая цена из `prices.json`; отсутствует — 1. Распределение базовых цен референса (505 строк): 0 — 13%, 2 — 8%, 4–5 — 24%, 6 — 33%, 7 — 9%, 8 — 4%, 10 — 3%, 12 — 5%. Смысл: 2 — базовые приёмы, 5–7 — обычное, 10–12 — сильное.

| Цена | Формула |
|---|---|
| Золото | база × 25 |
| Кристаллы, реликвия | база + (тир+1) × 4, не ниже 10 |
| Кристаллы, аркана | база + clamp(тир,1,4) × 5, не ниже 10 |
| Кристаллы, улучшение аркана | 50 |
| Кристаллы, проклятая реликвия в хабе | 25 |

### 9. Магазин предметов

5 слотов реликвий (шаг 1.625) и 1 слот лечения. Слот реликвии:
1. с шансом 3% — недостающая часть рецепта сборной реликвии, если у игрока есть другая часть (проклятость должна совпасть);
2. иначе — из пула без возврата (учитывая уже выставленные в магазине);
3. шанс скидки `sale_chance` = 0.15: цена −25 золота (то есть −1 единица базы); у проклятых скидок нет.

Пустой пул — слот исчезает. Купить нельзя, если реликвия уже есть, инвентарь полон (12) или проклятых ≥12. Эффект «перезапуск витрины» заменяет проданный слот новым броском.

Лечение: лечит max(50, ⌈макс.здоровье × (доля − 0.05 × число_покупок)⌉) всем живым и оживляет мёртвых; доля из данных.

### 10. Магазин арканов

Слоты: обычная новая аркана (скидка 15%, цена база × 25) и «улучшенный» слот, у которого:
- с шансом 0.45 предлагается улучшение уже имеющейся (цена 100 золота);
- с шансом 0.35 (при круге ≥1) — аркана особого тира (0.75, если у игрока «победная» реликвия), цена база × 25;
- иначе новая улучшенная — база × 25 + 50.

Пул арканов: тиры 0–4; строится при загрузке этапа, из него убираются выбранные и надетые у любого игрока; вычёркивание после выбора. Пул ограничен: тиры добавляются снизу вверх, пока число ещё не открытых не достигнет `locked_cap` (24), дальше тиры не добавляются.

### 11. Выпадение арканы

Для каждого выпавшего по §3 экземпляра: с шансом `prefer_new_spell` ищется ещё не открытая аркана; если нет — любая из пула. Для сундука босса: `signature_rate` = 1 — выпадает улучшенная версия имеющейся арканы (сигнатурная, если есть, иначе усиленная); нет таких — обычная новая.

## Критерии приёмки (headless)

1. Симуляция 100 забегов × 3 этапа × 2 стадии (фикс. сиды): ни разу реликвия не оказывается в инвентаре дважды; ни разу выдана вытесняемая при наличии вытесняющей.
2. На 100 000 убийств каждого класса частоты кристаллов, сердец, реликвий, арканов в пределах 3σ от таблицы §5 при фиксированных множителях.
3. Подстройка: монотонность множителя золота по собранному золоту, граничные значения 1.5 / 1.0 / 0.5 в точках 0 / 200 / ≥400; при побеждённых <50% — ровно 1; множитель сердца 1.75 при h=0 и 0.5 при h=1.
4. Кристаллы: сундук босса даёт 20/25/30/35/40 на сложностях 0, 1, 2, 3, ≥4.
5. Магазин: 1000 генераций — слоты различны, доля скидок 15%±3%, доля рецепта 3%±1.5%, ни одной скидки у проклятых.
6. Пул: один и тот же сид — тот же порядок выдачи; пустой выбранный пул переходит в запасной.
7. Все выставляемые в магазинах id имеют цену >0; `validate_content` ловит отсутствие.
8. Скриншот магазина с ценами и значком скидки.
