# 15 — Реликвии: система

## Цель

Игрок носит до 12 реликвий, и каждая меняет один из трёх рычагов: числа (статы), реакции на события боя и забега, правила мира (экономика, враги, комнаты). Реликвия — **строка данных + необязательный класс поведения**: примерно треть каталога (разделы А и Б в `15b`) вообще не требует кода, почти все остальные — параметризованный шаблон «событие → эффект». Срез закрыт, когда (а) любой тип триггера из §3 проходит свой headless-тест, (б) новая реликвия из существующих шаблонов добавляется только строкой в `data/relics.json`, (в) инвентарь, группы, рецепты и проклятия ведут себя по §2, §5–§10 на 1000 сидов без дублей и дрейфа.

Здесь — правила **системы**. Каталог всех реликвий с числами — `15b-relics-catalog.md`. Сквозная механика статов (виды модификаторов, приоритеты, округление, «долить до максимума») — `14-stat-modifiers.md`: здесь не переопределяется, реликвия лишь вешает и снимает модификаторы по id. Пул, тиры, цены, магазины — `09-loot.md` §6–§9 (здесь только то, что относится к самим реликвиям). Особые комнаты и NPC — `18-special-rooms.md`; хаб и лавки — `17-hub-services.md`; мета-открытие — `12-meta.md`; кооп — `13-coop-pvp.md`; гонка боссов — `19-boss-rush.md`.

Отличия от референса (по одной строке):
- Референс держит ~370 отдельных классов; у нас ~85% каталога выражается данными (≈37% — только мод-список или мод с условием, ≈47% — шаблон «событие → эффект»), класс поведения нужен ~15% реликвий (§1).
- Референс подписывает каждую реликвию на делегаты здоровья/навыков напрямую; у нас единая шина событий (§3) с фиксированным порядком обработчиков и общими правилами шанса и внутреннего кулдауна.
- Часть накопительных бонусов референса (+HP за удары, урон фирменной арканы, броня от урона) живёт в статическом хранилище и переживает выброс и повторный подбор; у нас это явное поле `persist` (§4).
- Известные дефекты референса не переносим: «проклятие x3 отбрасывания» никогда не срабатывает (условие сравнивает поле со строкой); у комплекта «радужный бегун» мод задержки разгона применяется дважды; название реликвии «крит после ухода из боя» не соответствует коду (проверки «вне боя» нет); «шанс» на эхо-удар фактически 100%. Мёртвый контент (26 строк, §11) не входит в пул, но схема его принимает.
- Реестры групп и рецептов, исключения и ICD лежат в данных, а не размазаны по классам.

## Поведение

### 1. Модель данных

Файл `data/relics.json`, одна строка на реликвию. Все числа — только здесь (инвариант проекта «числа в данных»).

| Поле | Тип | По умолчанию | Смысл |
|---|---|---|---|
| `id` | str | — | уникальный ключ (snake_case, свой) |
| `name_key` | str | — | ключ локализации имени и описания (27) |
| `category` | enum | `misc` | `offense` / `defense` / `misc` — вкладка в «сундуке реликвий» (17) |
| `tier` | int 0..4 или null | null | тир пула (09 §6); null — в пул не входит |
| `price` | int ≥ 0 | 0 | базовая цена (09 §8) |
| `flags` | set | пусто | `cursed`, `hub_only`, `not_for_sale`, `combine_only`, `destroy_on_drop` (смысл — §2, §5–§8, §11) |
| `group` | id или null | null | принадлежность к группе Г1–Г12 (§7) |
| `recipe` | id или null | null | реликвия — часть рецепта, id рецепта (§8) |
| `excl` | id или null | null | множество взаимоисключения (§9) |
| `persist` | enum | `instance` | `instance` (счётчик живёт в экземпляре, сбрасывается подбором) / `run` (по игроку на забег, переживает выброс) / `level` (сбрасывается загрузкой уровня) / `visit` (по игроку, живёт между уровнями до сброса забега; для «кулдаун между уровнями») (§4) |
| `curse` | {plus, minus, kind} | — | только для `cursed`: блоки плюса и минуса и класс недостатка (§5) |
| `behavior` | объект | — | см. ниже; ровно один вид |

**Виды поведения (`behavior.kind`):**

1. `mods` — статический список модификаторов (триггер STAT). Элемент: `{stat, op, value, priority=10, skills}`; `op` — вид из 14 п. 3 (`override`, `base`, `mult`, `add`, `late_mult`); `skills` — фильтр приёмов-получателей: `all_non_status` (по умолчанию), `no_basic_no_status`, `no_basic_dash_no_status`, `basic_only`, `dash_only`, `jump_only`, `movement_only`, `melee_only`, `projectile_only`, `summon_only`, `signature_only`, `empowered_only`, `unempowered_only`, `element:<e>`. Мод вешается при подборе, снимается при снятии (14 п. 12).
2. `mods_if` — те же моды, но включаются условием или масштабируются числом: `condition: {source, op, threshold}` или `scale: {source, per_unit, cap}`. Источники: `hp_frac` (доля здоровья владельца, 0..1), `hp_abs`, `gold`, `crystals`, `inventory_count` (контейнер группы считается числом своих частей, §7), `cursed_count`, `map_revealed` (доля раскрытой карты за забег), `distinct_elements`, `element_arcana_count:<e>` (число открытых арканов стихии), `partner_state` (соло / кооп один владелец / кооп оба). Пересчёт — на каждое изменение источника, а не по кадрам.
3. `on_event` — реакция: `{event, filter, chance=1, icd_s=0, window_s=0, window_policy, charges, effects[]}`. События и тесты — §3. Операции эффектов: `mod_window` (моды на `duration_s`), `spawn` (создать атаку/сущность по id приёма), `heal`, `give_gold`, `give_crystals`, `reduce_cooldowns` (абсолютные секунды или доля), `gain_overdrive`, `set_flag`, `damage_self`, `spawn_pickup` (сердца/золото/кристаллы), `grant_relic`, `remove_self`.
4. `scripted` — `class: "<id>"` из реестра поведений + `params{}`: для того, что шаблоном не выразить: воскрешение, долг, обмен инвентаря, автоусиление случайной арканы, катаклизмы, глобальные мультипликаторы забега. Класс обязан реализовать `activate(owner)` / `deactivate(owner)` (симметричные: после `deactivate` значения стат в точности как до `activate`, 14 критерии приёмки) и только публичные события §3.

**Валидатор (`validate_content`):** id и `name_key` уникальны; `tier` ∈ 0..4 или null; все ссылки (`group`, `recipe`, `excl`, `class`, `skills`) существуют; `stat`, `event`, `source`, `op` — из перечней; `cursed` требует `curse.plus` и `curse.minus` (кроме `hub_only`, где недостаток может быть «мир»); `hub_only` влечёт `cursed` (в референсе 20 из 20 хаб-реликвий проклятые); `combine_only` не имеет тира; группа: ≥ 2 члена, контейнер имеет `combine_only` и `destroy_on_drop`; рецепт: каждая часть и результат существуют, цикл невозможен; число в диапазоне (шансы 0..1, длительности ≥ 0); неизвестные поля — ошибка.

**Пример строк** (числа — из каталога 15b):

```json
{"id":"plain_might","category":"offense","tier":0,"price":6,
 "behavior":{"kind":"mods","mods":[{"stat":"damage","op":"mult","value":0.08,"skills":"all_non_status"}]}}

{"id":"wounded_might","category":"offense","tier":4,"price":6,
 "behavior":{"kind":"mods_if","condition":{"source":"hp_frac","op":"<=","threshold":0.3},
             "mods":[{"stat":"damage","op":"mult","value":0.15}]}}

{"id":"invuln_after_three_hits","category":"defense","tier":2,"price":6,
 "behavior":{"kind":"on_event","event":"hurt.actual","filter":{"damage_gt":0},
             "window_s":3,"window_policy":"refresh_on_event","count_to_fire":3,
             "icd_s":30,"effects":[{"op":"set_flag","flag":"invulnerable","duration_s":3}]}}
```

Оценка долей каталога 339 (по первичному триггеру, первый проход): `mods`/`mods_if` ≈ 127 (раздел А+Б, 37%); `on_event` ≈ 160; `scripted` ≈ 50. Раздел «Базовые классы» (С в `15b`, 30 строк) — не реликвии, а контракты шаблонов: они становятся нашими видами поведения и фильтрами.

### 2. Инвентарь и жизненный цикл

1. **Предел и счёт.** 12 слотов на игрока. Контейнер группы (§7) и сборные реликвии занимают **один** слот; части внутри контейнера слотов не занимают. Для реликвий, считающих число предметов (`inventory_count`), контейнер считается числом своих частей.
2. **Дубли.** Одна реликвия — один экземпляр на игрока: подбор уже имеющегося id отклоняется. Стаков одной реликвии нет; модификатор id реликвии заменяет сам себя (14 п. 7). Разные реликвии с одним статом складываются и перемножаются по правилам 14. В коопе реликвии не дублируются между игроками (13).
3. **Порядок добавления.** Шаги по порядку, первый отказ прерывает: (а) id уже есть → отказ; (б) взаимоисключение (§9): если у владельца среди множества есть проклятая — отказ, иначе все имеющиеся члены множества сбрасываются (выпадают на пол, если не `destroy_on_drop`); (в) инвентарь полон (≥ 12): если добавляемая реликвия **достраивает** группу или рецепт (§7, §8) — допускается сверх предела; иначе выбрасывается **первая по порядку добавления непроклятая** реликвия (на пол у ног, кроме `destroy_on_drop`; у референса — первая в порядке обхода словаря) и новая встаёт на её место; если все проклятые — отказ; в хабе и домашней комнате выбросить нельзя — подбор при полном инвентаре отказывает; (г) привязка к владельцу, `activate`; (д) событие «инвентарь изменён» всем подписчикам (реликвии со счётом).
4. **Снятие.** Обычное снятие (выброс игроком из меню по кнопке «взаимодействие» или вытеснение при подборе) проклятую реликвию **не снимает**: звук ошибки, ничего не происходит. **Принудительное** снятие (для рецептов, самоудаления, одноразовых) проклятость игнорирует. `destroy_on_drop` реликвия при выбросе исчезает безвозвратно (с уведомлением о потере), остальные падают на пол и подбираются обратно (с короткой задержкой подбора, 09/03).
5. **Очистка.** Смерть игрока и конец забега — снимается всё. Экипировка билда в хабе — всё, кроме проклятых (купленная в хабе проклятая сохраняется). «Случайный билд» (17) — всё, кроме `hub_only`. Гонка боссов (19) — удаляются все проклятые. При очистке части групп пропадают без выброса.
6. **Активация/деактивация** симметричны: `deactivate` вызывается и при упаковке реликвии в группу (затем она включается заново); итог стат — как до `activate`, без дрейфа (тест: 1000 циклов, 14).
7. **Старт.** Игрок начинает забег с одной «стартовой» реликвией: назначенная в сундуке реликвий (17) или `start_token` (тир 0, цена 2, не продаётся, эффекта нет). Назначенная проклятая отклоняется, подставляется стартовая по умолчанию. Реликвии `not_for_sale` (стартовая метка, пять наборов одной стихии, два сундука при выбросе) в пулы дропа и магазинов не входят: их получают только как стартовую или случайным билдом.
8. **Подсказка в UI** (25): значок «готово / активно / выключено» на панели реликвий для реликвий с кулдауном, окном или условием; красная аура и метка «проклятая» у проклятых.

### 3. Триггеры

#### 3.1. Общие правила шины событий

1. **Источник событий** — боевой конвейер (02, 04, 05) и сцена забега (11). Реликвия подписывается на событие при `activate` и отписывается при `deactivate`. Событие несёт полезную нагрузку (удар, цель, приём, число).
2. **Порядок обработчиков** одного события — порядок добавления реликвий в инвентарь владельца; члены группы идут в порядке состава группы (15b, реестр). Порядок детерминирован (инвариант 4 проекта).
3. **Шанс.** Каждый бросок — через `sim/rng.gd`, поток `hash(floor_seed, player_id, relic_id, roll_index)`, где `roll_index` растёт на каждый бросок этой реликвии. Лишний бросок другой реликвии порядок не сдвигает.
4. **Внутренний кулдаун (ICD).** Четыре вида: `cooldown` (запускается в момент срабатывания, длится `icd_s`, события в это время игнорируются), `window` (открывается первым событием, длится `window_s`; политика `refresh_on_event` — каждое событие перезапускает окно, `extend` — продлевает, `fixed` — не трогает), `charges` (N зарядов на уровень, восстанавливаются загрузкой уровня), `decay` (шанс умножается на коэффициент после каждого срабатывания и не восстанавливается). Кулдаун с `persist: visit` не сбрасывается загрузкой уровня.
5. **«Реально полученный урон»** — урон, дошедший до здоровья владельца: после уклонения, неуязвимости, парирующего стража и щита, ограниченный текущим здоровьем (событие `hurt.actual`, §3.2). Почти все реакции «при ударе по игроку» требуют `damage > 0` и не-статусного (не тик DoT) источника, если не сказано иное.
6. **«Чистое убийство»** — убит враг, который не мини-слизень, не призван и не порождён призывателем. Чьё это убийство: **наше решение** — убийцы (последний удар по цели от приёма его категории); у референса проверки владельца нет (событие приходит и для убийств партнёра), для реликвий мира владелец не важен.
7. **Глобальные эффекты** (множители золота и числа выпадающих реликвий, правила врагов) меняют общий для команды параметр; в коопе параметр снимается, только когда реликвии нет **ни у одного** игрока.
8. **Эффекты на врагов** применяются и к уже живым, и к появляющимся позже (подписка на событие `enemy.spawned`), и снимаются при снятии реликвии.
9. **Зависимость от типа сцены** задаётся полем `scenes: [stage|boss|hub|any]`: большинство реакций не работают в хабе; ряд проклятий пересчитывается на каждой загрузке сцены.
10. **Обращение к арканам.** «Число арканов стихии» считается один раз при `activate` по открытым (разблокированным в профиле) арканам; при открытии новых в забеге не пересчитывается.

#### 3.3. Точки конвейера урона по владельцу (HURT)

Порядок внутри обработки удара по живому владельцу (подробный конвейер — 02 §7, статы — 14 п. 13):

1. `hurt.enter` — удар принят к обработке, **до** критического броска и множителей; срабатывает для любого попадания по живому владельцу.
2. Если у владельца не включён страж «гасит следующий удар»: бросок крита атакующего и множитель получаемого урона; затем `hurt.pre_shield` — урон известен, щит ещё не вычтен. (При включённом страже шаги 2–4 пропускаются.)
3. Вычитается щит, применяются таблица стихии, получаемый урон и броня (14 п. 13).
4. `hurt.event` — урон рассчитан; сработает и тогда, когда удар **поглощается** щитом, страж гасит его или владелец неуязвим.
5. Проверки неуязвимости, стража, щита (удар гасится — дальше событий нет).
6. Вычитание из здоровья (не ниже 0; защита от смерти оставляет 1). `hurt.actual` — **реально полученный урон**, нагрузка с уже ограниченным уроном. Далее — смерть (если здоровье 0), иначе реакция на урон и статусы.

Реликвии выбирают точку: «до щита» (`hurt.pre_shield`), «событие» (`hurt.event`), «фактический» (`hurt.actual`, по умолчанию), «вход» (`hurt.enter`, редко). Сработает ли `hurt.actual`-реликвия на удар с уроном 0 — по референсу неоднозначно (одна проверяет `damage > 0`, остальные нет): у нас фильтр `damage_gt: 0` явный и по умолчанию включён.

### 4. Накопления и хранилища

Четыре вида счётчиков, `persist` задаёт, где они живут:

- **`instance`** — в экземпляре реликвии; сбрасывается подбором и отключением. Пример: `dmg_kill_streak_cap` (+1% за чистое убийство, потолок +20%; −5% при реальном уроне), `hop_streak_dmg` (+15% за прыжок, потолок +100%), `dash_chain_might` (+5%, потолок +15%), `crystals_to_dmg_pool_hex` (+0.1% урона за кристалл, потолок +20%). Счётчики убийств у `curse_hp_grows_with_kills` (шаг 1 п.п., предел +50% после 100 убийств) и `curse_dmg_grows_with_kills` (0.25 п.п., предел 0.5 за 200 убийств) обнуляются при каждом включении и выключении.
- **`run`** — по игроку на весь забег, переживает выброс и повторный подбор, сбрасывается только новым забегом. В референсе их шесть: максимум HP от лечения (+3 за лечение, до +75), от ударов (+2, до +75; у сборки +3, до +100), урон фирменной арканы (+1% за применение, до +50%), броня от полученного урона (2% + 0.01% за единицу, накопление до 1000), «банк карты» (доля раскрытой карты, копится на забег). **Решение у нас:** сохраняем это поведение явным `persist: run`; выброс и повторный подбор не обнуляют (иначе выброс-подбор давал бы сброс «минуса»).
- **`visit`** — кулдаун, живущий между уровнями (`dodge_full_after_hit`, `refresh_cd_low_hp` и т.п.).
- **`level`** — сбрасывается загрузкой уровня: заряд `lethal_hit_shield_once`, выбор `amp_random_each_level`.

Глобальные (не личные) модификаторы: множитель золота (+15% / −50% / +15% у трёх реликвий), плоский бонус кристаллов (+1 к дропу), число выпадающих реликвий (×2, дробь отбрасывается), шанс сердец (+50%) — общие для команды; в коопе снимаются, когда реликвии нет у обоих.

### 5. Проклятые реликвии

1. **Структура.** Каждая проклятая реликвия — «плюс + минус» (`curse.plus`, `curse.minus`) и класс недостатка `curse.kind`:
   - `stat_trade` — обмен статов (урон против HP, КД против получаемого урона, уклонение против крита и т.д.): `heavy_plate_dull_blade`, `crit_swap_dmg_curse`, `glass_crit_curse`, `curse_cd_half_dmgtaken_double`, `curse_dodge45_dmgtaken2`, `curse_dmg_up_hp_down` и др. (~35 строк);
   - `economy` — золото и цены: `toll_plating` (−5 золота за удар), `merchant_markup_might` (цены в золоте ×1.5), `usury_cash_advance`, `paid_arcana_might`, `curse_coin_to_restore_each_floor`, `curse_hp_to_coin_each_floor`, `crystals_to_coins_x3_hex`;
   - `world` — меняет врагов и уровень (все хаб-реликвии, §6);
   - `inventory` — вмешательство в инвентарь: `purge_for_might`, `swap_all_for_cursed`, `floor_hex_gift`, `curse_exit_compass`;
   - `loss` — случайная потеря: `curse_shop_discount_lose_item`.
2. **Нельзя снять.** Проклятая реликвия не выбрасывается вручную, не вытесняется при полном инвентаре (§2 п. 3 пропускает её), не удаляется обычным снятием (§2 п. 4).
3. **Как всё же пропадает.** (а) Самоудаление по условию: долг погашен (`usury_cash_advance`), `curse_exit_compass` после третьего найденного локатора (так же принудительно снимают себя и непроклятые одноразовые, например `coin_boss_weak_element_bounty`); (б) слияние в рецепт — обе части снимаются принудительно (§8); (в) очистка при смерти / конце забега; (г) гонка боссов снимает все проклятые на старте (19); (д) вход на финальную арену снимает два мировых проклятия — «любой удар = 99 урона» и «у всех 1 HP и урон 1».
4. **Предел.** Не более 12 проклятых у игрока. Подбор, покупка, добавление `floor_hex_gift` и `swap_all_for_cursed` отклоняются при ≥ 12.
5. **Получение.** (а) С шансом `curse_chance` = 0.1 бросок реликвии (дроп, сундук, слот магазина) идёт в **проклятый пул** (09 §6): все проклятые минус `hub_only` и `not_for_sale` (в референсе 50); (б) особая «проклятая лавка» — бесплатно, одну (18 §7); (в) «тёмная лавка» в хабе — одна проклятая из **хаб-пула** (только `hub_only`, 18 реликвий в пуле) за 25 кристаллов, раз за визит; после покупки остальные исчезают, выбор сохраняется до следующего визита (17); (г) недостающая проклятая часть рецепта с шансом 3% в слоте магазина (09 §9, проклятость части должна совпасть). Проклятые не зависят от открытия в профиле (всегда доступны). Цена в таблице 0; цены магазина к ним не применяются (скидка `sale_chance` не действует, 09 §9).
6. **Подача.** Красный свет и аура над выпавшей проклятой реликвией, звук отдельный от обычного, тег «проклятая» в описании (25, 03). Достижение «носить больше трёх» — 28.

### 6. Хаб-реликвии и модификаторы забега

Двадцать проклятых реликвий с флагом `hub_only` (18 в пуле, 2 вне пула) — **модификаторы забега**: они берутся только в хабе (§5 п. 5в), действуют на весь забег и в основном меняют мир, а не владельца. Выход из хаба и экипировка билда их сохраняют (§2 п. 5); «случайный билд» тоже.

Правила:
1. Эффект на врагов применяется к уже живым и к вновь появившимся (§3.1 п. 8) и обратимо снимается; для двух игроков — снимается, когда реликвии нет у обоих.
2. Эффект на игроков касается **всех** активных игроков команды, а не только владельца (`curse_all_hp_minus40`, `curse_all_hits_99`).
3. Два мировых проклятия (`curse_all_hits_99`, `everyone_one_hp_hex`) снимаются при входе на арену финального босса; для 1 HP/1 урон у финального босса вместо переопределения щита ставится особый мод щита хаоса с доливом до нового максимума (14 п. 10).
4. Эффекты, зависящие от генерации (`no_floor_pits_hex`, `wild_barrels_hex`, `curse_double_foes`), применяются при генерации этажа (07, 08): убрать клетки-ямы и обнулить шанс ям у декораций; добавить декорацию-бочку (шанс 0.08, не ближе 4 клеток друг к другу); удвоить число врагов (при −20% здоровью врагов).
5. Полный список с числами — раздел «Н» каталога 15b (`floor_hex_gift`, `curse_double_foes`, `curse_foe_hp_down_dmg_up`, `curse_all_hp_minus40`, `curse_fast_everyone`, `curse_boom_every_kill`, `curse_all_hits_99`, `curse_hp_down_full_refill_no_restore`, `curse_shop_discount_lose_item`, `no_floor_pits_hex`, `everyone_one_hp_hex`, `all_status_immune_dmg_up_hex`, `wild_disasters_hex`, `all_foes_elemental_hex`, `wild_barrels_hex`, `arcana_swap_after_use_hex`, `recharge_war_hex`, `soul_leech_hub`; вне пула — `missile_wall_blast_hex`, `slow_all_bolts`).

### 7. Группы (контейнеры)

Двенадцать групп по 3–6 реликвий (реестр — конец `15b`): шансы статусов (6), удар-стихия на лёгкую атаку (5), спутники-тараны (5), ауры (5), стойкость к стихиям (5), иммунитеты к статусам (5), скидки и витрина (5), бонусы от числа проклятых (3), локаторы (3), монеты (5), счёт арканов стихии (5), призыв (6).

1. **Контейнер** — реликвия-группа со флагами `combine_only`, `destroy_on_drop`, без собственного эффекта; не продаётся и не выпадает отдельно.
2. **Создание.** Когда у игрока оказывается вторая часть одной группы, создаётся контейнер **сверх предела инвентаря**; все имеющиеся части группы переносятся во внутренний инвентарь контейнера: снимаются из основного (с `deactivate`) и добавляются внутрь (с `activate`). Контейнер занимает один слот. Каждая следующая часть той же группы уходит внутрь сразу при подборе, даже при полном инвентаре (§2 п. 3в).
3. **Эффекты остаются у частей.** Группа бонуса за «полноту» не даёт (только отметка «n/N», при полном составе — звёздочка). Чтобы создание группы не удваивало эффект, у частей-«создателей» (аура, спутник, скидка, локатор, счёт арканов) во время переноса действует флаг «группа создана»: собственный эффект пропускается, потом включается один раз.
4. **События** внутреннего инвентаря пересылаются в основной (реликвии со счётом видят состав), `inventory_count` считает части.
5. **Выброс контейнера.** Если владелец жив — части падают на пол по одной, начиная с последней, затем контейнер исчезает; владелец мёртв — части стираются. Части внутри контейнера из пулов исключены (09 §7).
6. **Награда врача** (7 реликвий, 18 §3) — не группа, а пул `combine_only`; одна из них (`heal_shop_flat_25`) входит в группу «скидки».

### 8. Рецепты (сборные реликвии)

Десять рецептов (реестр — конец `15b`): лёд-пламя, странник, выпускник, фокусник, вампир, растущее HP с регеном, единорог, набор отбива, итоговый набор отбива, идеальный локатор.

1. **Слияние.** Подбор части при наличии остальных частей рецепта: все части удаляются **принудительно** (проклятость не мешает), результат выдаётся сверх предела инвентаря, собственный эффект части не применяется. Результат имеет `combine_only` и в пул не входит.
2. **Цепочка.** Результат рецепта может быть частью следующего: набор отбива + `riposte_surge_gain` → итоговый набор отбива.
3. **Вытеснение.** Владение результатом убирает из пула его части (09 §7), владение частью не мешает остальным.
4. **Недостающая часть в магазине** (09 §9): слот с шансом 3% выдаёт часть рецепта, которой у игрока нет, если у него есть другая часть; проклятость части должна совпасть с проклятостью уже имеющейся. Выбор части: перебор частей рецепта с конца (часть, которая у игрока уже есть, пропускается); если запрошена проклятая — берётся первая проклятая; иначе каждая берётся с шансом `1 / max(n−1, 1)`, а часть с индексом 0 — гарантированно, если до неё ничего не выбрано.
5. **Идеальный локатор** (Р10) собирается иначе: проклятый «компас выхода» сам поглощает три обычных локатора (из инвентаря и из группы локаторов); когда найдены все три, выдаётся результат, а компас исчезает.
6. **Наборы одной стихии** (пять реликвий, `not_for_sale`) — не рецепты, а условные: эффект включён, только если **все** назначенные слоты арканы и запасной слот заняты арканами одной стихии (проверка на каждую смену набора). Например, набор огня: урон огненных арканов +20% и шанс поджога 100%; воздуха — скорость +20% и замедление; земли — HP +20% и броня; молнии — крит +20% и шок; воды — лечение +50% и КД водных −30% (точные числа — 15b). Выдаются стартовой реликвией или «случайным билдом» (17), который подбирает арканы этой стихии.

### 9. Взаимоисключения и вытеснение

1. **Взаимоисключение В1/В2** (множество): в инвентаре держится одна. Подбор второй сбрасывает остальные (выпадают на пол); если среди имеющихся есть проклятая — подбор отклоняется (§2 п. 3б). Множества: три «запрета умений врагам» (В1, по типу брони врага); семь жетонов NPC (В2).
2. **Вытеснение (`excl` у результата)** — запрещает выпадение частей, §8 п. 3. Источник пула — 09 §6–§7.
3. **Групповые части** по отдельности в пул не возвращаются, пока у игрока контейнер (09 §7).
4. **Запрет умений врагам:** реликвия накладывает мод «запрет приёмов» на список типов врагов при подборе и после каждой загрузки уровня; защита от двойного наложения общим флагом «в силе».

### 10. Жетоны NPC-комнат

Семь реликвий-жетонов (тиры 1–3, базовая цена 5, В2): они **не имеют своей логики** — их проверяют NPC и генератор этажа (18).

| Жетон (own_id) | Тир | Что даёт |
|---|---|---|
| `token_bank` | 1 | банкир: коэффициент обмена 0.125 вместо 0.09, обмен возможен и при 0 золота, жетон тратится, на пол +19 кристаллов (18 §2) |
| `token_nurse` | 2 | врач: плата-аркана не берётся, 5 сердец вместо 3, жетон тратится (18 §3) |
| `token_shuffle` | 2 | тасовщик: жетон вместо потери случайной аркана (18 §4) |
| `token_tailor` | 3 | портной: улучшение облика без платы 100 золота и 100 HP (18 §6) |
| `token_well` | 3 | колодец реликвий: сданные реликвии ×2; сам жетон — ×3 цены (18 §5) |
| `token_pinata` | 3 | шар-сюрприз: первое попадание убивает, жетон тратится (18 §8) |
| `token_curse_shop` | 3 | определяет комнату этажа: проклятая лавка (если не отключена; в гонке боссов отключена) |

Правила: (1) если у любого из активных игроков есть жетон, особая комната следующего этажа определена им (при нескольких — первый найденный по порядку игроков); (2) расход — через обычное снятие жетона NPC (`remove_self` без принуждения); `token_curse_shop` расходуется самой лавкой; (3) жетоны выпадают как обычные реликвии (проклятые не бывают); (4) подбор жетона не открывает его в профиле (12); (5) жетоны лежат в обычном пуле и занимают слот.

### 11. Тиры, цены, пул: что относится именно к реликвиям

1. **Тир** 0–4 влияет на цену разблокировки и порядок набора «ещё не открытых» в пул (09 §6, `locked_cap` 24), не на шанс выпадения. Состав обычного пула дропа и магазинов — **207** реликвий (из них 7 жетонов): т0 — 24, т1 — 36, т2 — 41, т3 — 34, т4 — 72.
2. **Базовая цена** — из `prices`; формулы золота и кристаллов — 09 §8 (золото = база × 25; кристаллы = max(10, база + (тир + 1) × 4)). Для обычного пула: 2 — 1 реликвия, 3 — 6, 4 — 20, 5 — 62 (с жетонами), 6 — 84, 7 — 22, 8 — 8, 10 — 1, 12 — 3; у проклятых, контейнеров групп, сборных и наград врача цена 0 или не используется.
3. **Флаги.** `not_for_sale` — реликвия исключается из **всех** пулов дропа и магазинов (стартовая метка, пять наборов одной стихии, два сундука при выбросе); при этом открывается покупкой в хабе как обычная. `combine_only` — исключена из пулов, получается слиянием, наградой NPC или победой (победная реликвия). `hub_only` — только хаб-пул (§6). `destroy_on_drop` — расходуется при выбросе: `pocket_hoard` (золото min(1000, 50V), кристаллы min(50, 5V), сердца min(5, V), где V = min(20, 9×круги + 3×ярусы + этапы с подбора)), `cache_of_arcana`/`cache_of_relics` (выпадает N = clamp(3×круг + 2×ярус + 1, 1, 5) штук), `revive_pack` (при выбросе непотраченной — 5 сердец), `pristine_might`, `flawless_boss_stack`, `death_save_halving_chance`, `five_charge_hit_shield`.
4. **Вне пула** (26 строк в 15b, раздел Р): есть в данных, но не регистрируются в пулах — вырезанное или заготовки; схема их принимает, `validate_content` помечает `tier: null` и не добавляет в пул.
5. **Стартовая и победная.** `start_token` открыта всегда. Победная реликвия (`chaos_set_crit_dmg`, `combine_only`) открывается концовкой (12, 11) и после этого доступна в сундуке реликвий как стартовая (17 §2); из пулов дропа исключена.

### 12. Стыки

- **Кооп (13).** Реликвии у игроков раздельные; «дружба» (`duo_bond_buff`) даёт +5% / +12.5% / +15% к урону и скорости; глобальные моды — §4. Событие смерти партнёра / воскрешение — DEATH.
- **Гонка боссов (19).** На старте режима снимаются все проклятые; в первой проклятой лавке первого этапа первой позицией стоит «двойной удар» (проклятая: урон по врагам и по игроку ×2, набор ульты −50%).
- **Мета (12).** Реликвия открывается покупкой в хабе за кристаллы; подбор в забеге не открывает; проклятые не требуют открытия.
- **Хаб (17).** Сундук реликвий (просмотр, назначение стартовой), тёмная лавка, случайный билд.

## Открытые вопросы

1. Что делать с 26 строками «вне пула»: оставить как отключённые данные (по умолчанию) или вернуть часть в игру (например, «регенерация при высоком HP», «подъём без урона»).
2. «Броня» реликвий выражена адд. прибавкой (+0.05 … +0.25); точная трактовка (доля снижения урона, потолок 1) — 14 п. 13; потолок суммы при стеке нескольких реликвий не задан.
3. Срабатывают ли реакции `hurt.actual` на удар с уроном 0 — в референсе неоднозначно; у нас явный `damage_gt: 0`.
4. Остаётся ли хаб-проклятие в инвентаре при возврате в хаб после смерти (в референсе экипировка билда и смерть различаются — проверить на живом клиенте).
5. Учитывать ли в `inventory_count` вложенные проклятые части контейнера (в референсе контейнер состоит только из непроклятых).
6. Баланс: тир 4 содержит 72 из 207 реликвий и дешёвые условные статы; разделить ли на два тира.
7. «Число арканов стихии» считается по открытым в профиле; нужно ли пересчитывать при открытии в забеге.
8. Реликвия «платить кристаллами» проверяет «проклятых меньше 12» — похоже на ошибку копирования условия; у нас условие — «кристаллов хватает».
9. Порядок обработчиков: у референса определяется порядком подписки делегатов; у нас — порядком добавления. Различие видно только у реликвий, меняющих один и тот же параметр удара на одной точке.
