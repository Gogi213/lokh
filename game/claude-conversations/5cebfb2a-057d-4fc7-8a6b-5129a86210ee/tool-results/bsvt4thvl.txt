# 03 — «Сочность»: тряска, вспышки, искры, цифры, hitstop

## Цель среза

Те же удары из среза 2, но с откликом: у обычного попадания нет остановки времени, сила отклика растёт с уроном; остановка времени зарезервирована за редкими событиями. Проверка — сравнение «до/после» на видео.

## Поведение

1. **Принцип.** Обычный удар сочнится тряской, вспышкой, искрой, цифрой, звуком, отбрасыванием и оглушением. Hitstop (замедление времени) — только на событиях: парирование, супер-крит, ульта, смерть игрока.
2. **Тряска камеры: сила.** Базовая сила 12; при попадании множитель = min(урон × 0.02, 2), итоговая сила = 12 × множитель. Урон 8 → ×0.16; 16 → ×0.32; 50 → ×1; предел ×2 при уроне ≥ 100. Эффекты без урона (событие, ульта) вызывают тряску с множителем 1. Удар, помеченный «без тряски», её не вызывает. Заряженный третий удар — отдельные ×0.35, обычное появление объекта удара — ×0.25 (при появлении, до попадания); парирование — ×0.1.
3. **Тряска: форма.** Длительность одной тряски 0.15 с. Каждые 0.0166 с к позиции камеры добавляется смещение в случайном направлении длиной сила × 0.0166 (при ×1: 0.2 м за шаг; ~9 шагов). Смещения накапливаются (случайное блуждание), камера не возвращается плавно. Одновременно допускается не более 4 тряск; пятая и далее игнорируется (кроме «принудительных»). Пока идёт любая тряска, камера держит смещение относительно игрока (следует за ним с тем же сдвигом); когда последняя закончилась — мгновенный возврат на точное слежение. Если камера дальше 3 м от игрока, тряска не включается. Глобальный множитель настройки «тряска» умножает силу (0 — выключено).
4. **Вспышка цели.** При получении урона (не при парировании и не при щите) спрайт цели на 0.1 с заливается цветом (для игрока красный 0.6/0.1/0.1) на полную силу, затем сразу снимается. Только если включён флаг «вспышка».
5. **Вспышка экрана при уроне игроку.** Красная виньетка; анимация проигрывается с нормализованного времени 1 − clamp(урон / макс. здоровье × 5.5, 0.525, 1): чем сильнее удар, тем раньше в анимации стартуем (ярче и дольше). Минимальный старт 0 (урон ≥ 18% здоровья), максимальный 0.475.
6. **Искры.** Размер по финальному урону: > 49 — большая, > 24 — средняя, иначе малая. Искра вылетает вдоль линии от атакующего к цели. Искры по игроку — красные (214, 11, 11). Парирование — всегда большая искра. Падение в яму — средняя. Нет искры при парировании цели-блока, при щите и при флаге «без эффекта».
7. **Цифры урона.** Показ цифры = целое финальное значение урона. Размер ∝ урон / макс. здоровье цели × 5 (для крита ×множитель крита). Усиленный (итог больше «чистого» расчёта) — оранжевый, ×1.1 и значок «вверх»; ослабленный (итог меньше) — голубой, ×0.9 и значок «вниз». Урон по игроку — тёмно-красный, по врагу — белый, по щиту — с голубой каймой. Парирование — текст «блок» белым размером 0.5; неуязвимость — серый «блок» размером 0.5 (или пустой, если сообщение выключено); уклонение — отдельный текст. Крит — флаг для эффекта (больший вес и отдельный звук тяжёлого удара). Цифра появляется у хёртбокса цели. Статусные тики показывают цифры (кроме «без цифры»), но первый тик статуса без искры и звука удара.
8. **Звук удара** — по подстихии удара (физический лёгкий, огонь, воздух, земля, молния, вода, лёд, яд, хаос); при крите дополнительно тяжёлый удар; при парировании — свой звук; при щите — свой.
9. **Hitstop только на событиях.** Реализация: на заданное **реальное** время умножить скорость симуляции на малое число и вернуть.
   - Парирование: 0.0625 с реального времени, скейл 0.01, возврат «ease-out» (плавное возвращение): скейл(t) = 1 − 0.99 × sqrt(остаток / длительность). Прерывает любую предыдущую задержку.
   - Супер-крит (редкий бонус: 2% от каждого крита, +300 урона, множитель крита 1): 0.2 с, скейл 0.01, ease-out.
   - Ульта (активация шкалы) и смерть игрока (и босса): сначала жёсткая заморозка 0.35 с при скейле 0.01 без возврата, затем сразу 0.5 с ease-out, плюс тряска ×1.
   - Повторные запросы: без флага «сбросить предыдущие» берётся меньший скейл и большее время (не суммируется, кроме случая, когда остаток короче).
   - Кадры-заморозки (опционально) — N × 1/60 с при скейле 0.
10. **Что не делает hitstop.** Обычный удар, обычный крит, DoT-тик, падение. Улучшение референса: все задержки и тряски идут через одну очередь событий симуляции с детерминированной длительностью в тиках, а не через корутины на реальном времени; видимая часть (камера, вспышки) читает очередь.

## Критерии приёмки

Headless:
- Функция тряски: урон 8 → 1.92 силы, 50 → 12, 120 → 24 (предел); пятая одновременная тряска игнорируется; через 0.15 с счётчик возвращается в 0.
- Выбор искры для урона 24 / 25 / 49 / 50 → малая / средняя / средняя / большая.
- Стартовая доля вспышки экрана при HP 500: урон 25 → 0.475 (нижняя граница clamp), урон 50 → 0.45, урон 100 → 0.0.
- Очередь замедления: парирование даёт ровно 0.0625 с (≈ 6 тиков реального времени по 0.01 с), скейл на старте 0.01, на конце 1.0; обычный удар очередь не трогает (тест «100 ударов — скейл всегда 1»).
- Тот же сид и инпуты → тот же хеш (hitstop детерминирован).

Визуально/на ощупь (видео «до/после»): удар 8 урона слабо дёргает кадр, 50 — ощутимо; нет «жвачки» времени на обычных ударах; парирование «щёлкает» — остановка почти незаметна по длительности, но читается; ульта — мощный кадр-стоп с мягким выходом; цифры читаются с первого взгляда по размеру/цвету.

## Открытые вопросы

1. Точные текстуры/частицы искр и вид виньетки — свои (ассеты референса не используются); параметры частиц подбираются глазами.
2. Умножение тряски в кооп-режиме и отдельный множитель «тряска» в настройках — вне среза.
3. Сохранять ли цифры урона от статусов при большом числе целей (шум) — решить при плотных сценах.
4. Точный спад сквозь ease-out (корень или квадрат) подтверждён кодом как корень; проверить на видео ощущение «хвоста».

# 04 — Парирование рывком, статусы, стихийный иммунитет, шкала ульты

## Цель среза

Игрок парирует удары рывком/стойкой без отдельной кнопки; цели получают статусы (поджог, яд, шок, заморозка, замедление, корни); работают стихийные иммунитеты и сопротивления; шкала ульты копится, затухает и тратится. По тесту на каждый статус.

## Поведение: парирование

1. **Включение.** Парирование — возможность, выдаваемая вещью; по умолчанию выключена. В срезе — булев флаг «парирование включено», в тестовой сборке включён. Статусные тики (DoT, падение) парировать нельзя.
2. **Окно.** Проверка идёт в момент попадания, до расчёта урона. Парирование возможно в состояниях: рывок, скольжение, парирование (само на себя), покой; в беге — только пока активно «окно бега»: 0.25 с после входа в бег и 0.25 с после разворота ввода более чем на 100° между соседними кадрами. Вне этих состояний (удар, оглушение, заморозка, падение) — нет.
3. **Условие.** Угол между текущим вектором ввода движения (не прицела, не направлением рывка) и направлением «на атакующего» ≤ 50°. Нулевой ввод считается совпадением (угол 0): стоя неподвижно в покое/рывке/скольжении игрок парирует любой удар — иначе строка «покой» была бы бессмысленной. Не парируется: уже заблокированный удар, статусный урон.
3a. **Только однократно:** блокируется один удар; флаг «защита» выставляется и тут же расходуется этим ударом.
4. **Эффекты** (в таком порядке): удар не наносит урона и не оглушает (цифра «блок», звук блока); большая искра между атакующим и целью; тряска ×0.1; hitstop 0.0625 с реального времени, скейл 0.01, ease-out (ранее запущенные задержки отменяются); игрок поворачивается лицом к атакующему и отскакивает от него со скоростью 7 м/с на 0.25 с; затем — приёмы, бег или покой (как после скольжения: проверка нажатых приёмов, ввод → бег, иначе покой). Состояние парирования допускает самопереход (подряд несколько парирований). Событие «парирование» доступно вещам (лечение, оглушающий взрыв и т. п. — вне среза).
5. **Улучшение референса.** Буфер 100 мс на нажатие рывка перед ударом; неподвижное парирование оставляем (как у референса), но выносим в параметр «нейтральный ввод парирует».

## Поведение: статусы

6. **Источник.** Любой удар несёт шансы и уровни статусов (поля шанса/уровня на поджог, замедление, яд, шок, заморозку, хаос, корни) и длительность заморозки/корней. Шанс — бросок от 0 до 1 из sim/rng; успешен, если шанс × сопротивление цели > значения броска.
7. **Порядок после попадания** (когда цель не мертва): сначала проверяется статус стихии самого удара; затем **один** дополнительный статус другой стихии в порядке вода → молния → огонь → земля → воздух (первый сработавший останавливает перебор); затем корни. Если сработала заморозка — цель замирает вместо оглушения; иначе цель получает оглушение. Это позволяет удару одной стихии нести статус другой.
8. **Статусные тики — общие правила.** Число тиков = floor(длительность / интервал). Первый тик сразу при наложении (без искры и звука удара), остальные каждые интервал. Тик — обычное попадание статусного типа: не крит, не режется бронёй и множителем получаемого урона, элементный множитель применяется, оглушает по множителю из таблицы, шкалу ульты не копит (множитель 0), нет отбрасывания (яд — в случайном направлении при множителе 0, то есть без него). Тик не бьёт мёртвую цель; цель, умершая от тика, умирает как обычно.
9. **Повторное наложение.** Тот же статус: если новый уровень ≥ текущего — уровень повышается, параметры пересчитываются, остаток тиков становится max(остаток, число тиков нового); уровень ниже — игнорируется. Статусы не складываются.
10. **Поджог.** Тики по 0.25 с, оглушение не вызывает (`canHitStun` = ложь).
11. **Яд.** Тики по 5 урона; интервал зависит от уровня; вызывает короткое оглушение (×0.25) на каждый тик; общая длительность 7.55 с.
12. **Шок.** Тики по 2 урона каждые 0.125 с; оглушение ×0.75 на каждый тик (цель «дрожит»).
13. **Хаос-статус.** Урон 5 каждые 0.15 с; длительность растёт с уровнем.
14. **Заморозка.** Цель входит в состояние «заморожен» (отбрасывание применяется, действовать нельзя) на длительность = freezeDuration удара (по умолчанию 1.5 с) **× 1.5**. Шанс = шанс заморозки × сопротивление воды. Любой удар без заморозки сразу размораживает цель (переход в оглушение/покой); удар с заморозкой тем же ключом атаки на уже замороженного обновляет таймер (кроме первого удара базовой серии). Цели стихии воды, с флагом «без заморозки» или без состояния «заморожен» не замораживаются.
15. **Замедление.** Снижает скорость движения **и** рывка цели на долю по уровню; длительность по уровню; пока цель не в состоянии движения/погони, эффект подавлен визуально, но таймер идёт. Повтор обновляет таймер полностью.
16. **Корни.** Скорость движения и рывка цели = 0 на время rootDuration (по умолчанию 2 с, в PvP по игроку ×0.4); отбрасывание цели игнорируется; атаки цели не запрещены.
17. **Стихийный иммунитет и сопротивления.** Цель стихии X не получает статус X: огонь — поджог, воздух — замедление, земля — яд, молния — шок, вода — заморозка. Корни иммунитета по стихии не имеют, но игнорируются флагом «без захватов». Для каждой стихии есть отдельный флаг «игнорировать» и множитель сопротивления (по умолчанию 1) на шанс статуса. Хаос статусам не иммунен.
18. **Элементный множитель урона.** Цель стихии E, удар стихии D: D = E → ×0.8; E уязвима к D (вода > огонь > воздух > земля > молния > вода; уязвима = побеждена) → ×1.2; D побеждается E → ×0.9; иначе ×1; нейтральный — ×1. Множитель применяется и к тикам.
19. **Очистка при стихийном рывке.** Рывок с готовым зарядом очищает у игрока противоположные статусы: огонь — замедление; воздух — яд; земля — шок; молния — заморозка; вода — поджог; хаос — всё.

## Поведение: шкала ульты

20. **Прирост.** За попадание по врагу: 0.25 × финальный урон × множитель приёма (из данных, по умолчанию 1). По разрушаемому: 3 × множитель приёма. По игроку (PvP): как по врагу. Нулевое значение (статусы, ультимативные приёмы, предметные атаки) — без прироста. «Один раз за взмах»: ключ (экземпляр атаки, приём) — повторное попадание тем же экземпляром не даёт прироста; для приёмов с флагом «общий прирост» — один раз на весь экземпляр, без — раз на момент времени. Ультимативные удары прироста не дают; пока шкала готова — прироста нет.
21. **Затухание.** Шкала 0–100 (внутренний минимум 0.01). После любого прироста затухание на паузе 0.75 с. Затем −4.5 в секунду (набор) / −10 в секунду (готова).
22. **Готовность.** При достижении 100 — «готова»: вспышка, контур; перезарядка сигнатурного приёма сбрасывается; затухание −10/с, то есть ≈ 10 с окна (+ пауза не возобновляется приростом). При падении до минимума — «истекла», звук.
23. **Активация.** Игрок держит кнопку слота сигнатурного приёма в готовом состоянии, не в воздухе, не мёртв/упал/заморожен: жёсткая заморозка 0.35 с + ease-out 0.5 с (см. 03), неуязвимость 0.25 с, тряска ×1, круг пыли, приём исполняется как ульта: урон ×множитель ульты приёма (по умолчанию 1), шкала → минимум. Улучшение референса: нажатие (а не удержание) + буфер 100 мс.
24. **Множители приёмов (из данных).** 0 — 51 запись (статусы, предметные атаки, призывы); 0.75 — 30; 0.5 — 12; 0.35 — 9; 0.25 — 3; 1.25 — 2; 1 — по умолчанию (быстрые потоковые приёмы 0.1–0.35). Разные по ударам массивы допустимы.

Статусы от врагов по игроку — уровень 1 (поджог 2×8, шок 2×5 с оглушением ×0.25, яд 5×5, хаос 5×5).

| Прочее | Значение |
|---|---|
| Элементный множитель | ×1.2 / ×0.9 / ×0.8 |
| Окно бега для парирования | 0.25 с; разворот > 100° |
| Угол парирования | ≤ 50° |
| Отскок после парирования | 7 м/с × 0.25 с |
| Hitstop парирования | 0.0625 с @0.01 |
| Шкала: максимум / пауза / затухание набор / готова | 100 / 0.75 с / 4.5 / 10 в секунду |
| Прирост по врагу / по разрушаемому | 0.25 × урон × m / 3 × m |
| Активация: заморозка / неуязвимость | 0.35 + 0.5 с / 0.25 с |

## Критерии приёмки

Headless (по тесту на статус):
- Поджог уровня 1 по манекену: 8 тиков, суммарно 16, первый тик в тик наложения; повтор уровня 3 за 1 с продлевает и повышает урон тика до 6; уровень 1 после уровня 3 игнорируется.
- Яд уровня 1: 5 тиков по 5, через 1.5 с; шок: 5 тиков по 2 с оглушением; нулевой шанс — без статуса.
- Заморозка 2.25 с (при freezeDuration 1.5); удар без заморозки прерывает её; цель стихии воды не замерзает; огненная цель не горит, воздушная не замедляется, земляная не травится, молниевая не шокируется.
- Замедление уровня 2: скорость цели 50%; корни 2 с: скорость 0, отбрасывание игнорируется.
- Каскад: огненный удар с шансами 1 на замедление и шок даёт шок (порядок молния раньше земли/воздуха) и не даёт замедление.
- Парирование: удар по игроку в рывке с вводом на атакующего (угол ≤ 50°) — урон 0, отскок 7 м/с 0.25 с, hitstop 0.0625 с; угол 60° — урон проходит; статусный тик не парируется; нулевой ввод в покое — парирует.
- Шкала: удар 40 урона по врагу с множителем 1 → +10; пауза 0.75 с, потом −4.5/с; при 100 — готова, окно ≈ 10 с; активация обнуляет и даёт неуязвимость 0.25 с.
- Тот же сид и инпуты → тот же хеш.

Визуально/на ощупь: парирование ощущается «щелчком» без остановки игры; статусы различимы цветом/эффектом; шкала читается в HUD, активация — событие.

## Открытые вопросы

1. Базовая длина оглушения и затухание отбрасывания (см. 02) влияют на ощущение шока и яда (оглушение на каждый тик) — нужна калибровка.
2. Нулевой ввод как парирование — вероятно намеренно (состояние «покой»); при плохом ощущении сделать параметром.
3. Шансы супер-крита и прочих вещей — вне среза.
4. Корни и замедление цели вне состояния движения: подавление визуала у замедления взято из кода, на практике ощущение проверить.

# 05. Арканы: слоты, архетипы, данные, ульта

Срез 5. Каталог приёмов с числами — `05b-arcana-catalog.md`. Статусы и парирование — `04-status-parry.md`.
Аркана = **один подкласс архетипа (или ни одного) + одна строка JSON**. Числа живут только в JSON.

## 1. Слоты и ввод

Шесть ячеек, индекс 0..5. Правила состава:
- ровно одна **базовая** (комбо без перезарядки) и ровно один **рывок**; остальные 4 — **стандартные**;
- одна стандартная может быть **фирменной** (флаг на ячейке, не на приёме): она автоматически усилена и только она получает ульту;
- срез 5 играбелен на 5 ячейках (базовая, рывок, 2 стандартные, фирменная); шестая зарезервирована, ядро хранит массив из 6.

Ввод (свои умолчания; привязки референса лежат вне кода): слот 0 — ЛКМ / запад на геймпаде, 1 — Пробел / юг, 2 — ПКМ, 3 — Q, 4 — E, 5 — R. Действие слота: `skill_0..skill_5`.
- Каждый кадр слоты опрашиваются по возрастанию; побеждает первый нажатый и готовый. Нажатие во время другого приёма срабатывает после его **порога отмены**.
- Референс буфера ввода не имеет; у нас буфер 100 мс (в разборе рекомендовано 80–120).
- Подбор: базовая и рывок заменяют текущую того же типа; остальные идут в первую пустую ячейку; пустых нет — в «запас» до экипировки.
- У любого приёма три порога доли анимации: **отмена** (можно начать другой слот; умолч. 0.6), **бег** (0.8), **выход в покой** (1.0). Типично: отмена 0.5–0.8, бег 0.7–0.9. Рывок доступен как отмена почти всегда.

## 2. Схема данных

Один объект на приём. Поля-массивы индексируются **стадией**: индекс = стадия − 1 (удар комбо, фаза приёма, вариант каста).
Правила массивов: длина ≤ 5 (лишнее отбрасывается); короче — добивается **последним значением**; поле отсутствует — все 5 значений равны умолчанию. `targets` не добивается.

| Поле | Тип | Умолчание | Смысл |
|---|---|---|---|
| id, element, sub_element | строка, enum | — / нейтр. / = element | под-стихия (лёд, яд, растение) влияет на статус и цвет |
| archetype | enum | обязательно | см. §5 |
| damage | int[] | 0 | урон стадии |
| cooldown | float[] | 0 | с; у зарядных — интервал возврата одного заряда |
| knockback | float[] | 0 | множитель отбрасывания; <0 — притяжение |
| knockback_override | bool[] | false | направление отброса = направление атаки, а не от центра |
| stun_mod, can_stun | float[], bool[] | 1.0, true | оглушение |
| same_target_immunity / same_attack_immunity | float[] | 0 | с до повторного удара той же цели: тем же хитбоксом / тем же приёмом (= частота тиков) |
| duration, tick_interval | float[] | 0 | зоны, ауры, призывы, DoT |
| count, max_hp | int[] | 0 | призывы, снаряды, заряды |
| crit_chance, crit_mult | float[] | 0.05, 1.5 | |
| burn/slow/poison/shock/chaos `_chance`, `_level` | float[], int[] | 0, 1 | шанс 0..1 за удар; уровень 1..5 |
| freeze_chance, freeze_duration | float[] | 0, 1.5 | |
| root_chance, root_duration | float[] | 0, 2.0 | |
| od_gain_mult | float[] | 1.0 | набор ульты (0 — не копит) |
| od_single | bool[] | false | набор один раз на объект атаки, а не на каждый тик |
| od_damage_mult | float[] | 1.0 | урон при касте-ульте |
| show_number, show_hit_fx, shake_camera | bool[] | true | |

Обязательны `id`, `element`, `archetype`, `targets` (кого бьёт: враг, разрушаемое). Остальное опционально.

**Лучше референса:** (а) схему проверяет валидатор: диапазоны (шанс 0..1, уровень 1..5, стадий ≤ 5), неизвестные поля — ошибка; (б) число зарядов, ударов комбо, размеры и пороги в референсе зашиты в код — у нас поля (`charges`, `hits`, `params{}`); (в) усиление и ульта — явные блоки `empowered{}` и `overdrive{}` с переопределениями, а не неявные «следующие индексы»; (г) архетип — enum, а не ~40 несвязанных классов-одиночек.

## 3. Перезарядка

- Старт по умолчанию — **в начале каста**. Флаг `cd_on_exit` — по окончании (удержание, зарядка, лучи). Флаг `smart_cd` — один старт на цепочку (двойной прыжок).
- **Зарядные приёмы**: `charges` (макс.) и `cooldown` = интервал возврата **одного** заряда; заряды возвращаются по очереди. Готов, если заряд > 0 и прошла пауза между зарядами (0–0.125 с). Каст тратит 1 заряд; цепочка/луч — по заряду на выстрел.
- **Рывок**: перезарядка не блокирует сам рывок, а только стихийный эффект (проверяется при входе). Рывок 0.125 с, затем скольжение 0.25 с (`01-player.md`).
- Фирменный приём получает **полный сброс** перезарядки в момент, когда ульта готова.
- API кулдауна поддерживает «уменьшить остаток на X» и «сбросить все» (нужно предметам).
- **Связь урон–перезарядка** (127 приёмов с прямым уроном, КД 3–8 с): строгой пропорции нет (корреляция ≈ 0), но есть бюджет. Сумма `damage` за каст ≈ **6 × КД** (медианы: КД 3–4.5 → 25; 4.5–5.5 → 28; 5.5–6 → 38). Пик одного удара: ~15 при КД 4, ~25 при КД 5.5–6, 50–75 у «нюков». Статус со 100 % шансом платится уроном (2–4 урона на секунду КД вместо 6). Телеграфируемые и условные приёмы выше нормы (метеор 23/с, спираль 31/с). КД ≥ 7 — призыв/зона с тиками, урон за каст несравним. Зарядные с КД ≤ 1 с живут по DPS: 10–13 урона за секунду стрельбы.

## 4. Усиление и ульта (овердрайв)

**Усиленная версия** — постоянная, у фирменной ячейки. Типично: +1…+2 снаряда/волны (3→5, 7→9, 2→3), размер/толщина ×1.5, зарядка ×0.5, другая стадия массивов (заморозка 2.5→2.75 с), доп. эффект.

**Шкала овердрайва** 0..100 (минимум 0.01):
- Набор за попадание по врагу: `0.25 × damage × od_gain_mult`; по разрушаемому: `3 × od_gain_mult`. DoT, призывы и ульта не копят; при полной шкале набор стоит.
- После любого набора пауза 0.75 с, затем спад 4.5/с. Шкала 100 → **готово**: свечение, сброс КД фирменной, спад 10/с (≈10 с на каст).
- **Каст ульты**: удержание кнопки фирменной ячейки (не в воздухе, не мёртв, не заморожен). Неуязвимость 0.25 с, короткий hitstop с плавным возвратом времени, тряска, шкала → минимум. КД не требуется и не стартует.
- Ульта — тот же приём с флагом `overdrive`: берёт **следующие стадии** массивов (обычный каст — стадия 1), больше снарядов/ударов, урон × `od_damage_mult`. Примеры: луч — тик 0.125→0.08 с, 15 выстрелов, 5 лучей; прыжок — 4 подряд.

## 5. Архетипы и общее поведение

| Архетип | Общее поведение |
|---|---|
| melee_combo | `hits` ≤ 5, удар i = стадия i. Хитбокс в доле анимации exec (0–0.3). Повторное нажатие в окне — следующий удар; финал: больший масштаб, поздние пороги бега/выхода; самоповтор без отпускания кнопки запрещён (кроме авто-удержания). Каждый удар сдвигает вдоль прицела. |
| projectile | Замах → выстрел в exec. Параметры: `count`, веер, скорость, время полёта. Подтипы: `hold` (целится при удержании, выстрел при отпускании), `charge` (полоса каста, мин/макс заряд), `chain` (серия с задержкой, заряд на выстрел). |
| dash | 0.125 с, направление — ввод; эффект только при готовом КД; стадия 1 — шлейф, последняя — взрыв; 1–2 заряда; затем скольжение. |
| ward | До 6 неподвижных стражей дугой радиуса 3 м вокруг игрока; у каждого `max_hp`, `duration`, периодическая атака, шанс статуса. |
| jump | Дуга к цели в пределах `range` (5.5), время/высота/баланс подъёма; в воздухе нет хёртбокса; после посадки задержка и удар; цепочки через `smart_cd`. |
| zone | Объект с `duration` и `tick_interval`; урон по `same_target_immunity`; подтип `aura` привязан к игроку (бафф на `duration`). |
| beam | «Боезапас»: `charges` = тики, старт при ≥ `min_ready` (5), тик каждые `shot_delay` (0.125 с), прицел поворачивается с ограниченной скоростью. |
| summon | `count`, `max_hp`, `duration` (10), КД 15, `od_gain_mult` 0; призыв бьёт сам. |

## 6. Эффекты стихий

| Стихия | Статус на ударах | Числа по уровню 1..5 |
|---|---|---|
| Огонь | поджог | тик 0.25 с, урон 2/4/6/7/8, длит. 2.05→1.55 |
| Вода (лёд) | заморозка | длительность из данных (1.5–3 с) |
| Воздух | замедление | уровень = сила |
| Земля | яд (+ корни у растений) | урон 5, тик 1.5→0.75 с, 7.55 с |
| Молния | шок | тик 0.125 с, урон 2, длит. 0.7→1.55 |
| Хаос | хаос-DoT или все статусы разом | тик 0.15 с, урон 5, длит. 0.8→1.55 |

Шанс — отдельный бросок на каждый удар. Враг своей стихии статусу не подвержен.

## 7. Приёмка

- Новая аркана = одна строка JSON и не более одного подкласса архетипа; правка баланса — без кода.
- Валидатор отвергает неизвестное поле, шанс вне 0..1, стадий > 5, архетип вне enum.
- Headless-тест на **каждый архетип**: стадии → урон, КД/заряды, пороги отмены, хеш реплея.
- Тесты сквозных правил: формула набора шкалы, пауза/спад, каст ульты, сброс КД фирменной, добивка массивов.
- Один визуальный чек на архетип (скриншот хитбокса и эффекта).
