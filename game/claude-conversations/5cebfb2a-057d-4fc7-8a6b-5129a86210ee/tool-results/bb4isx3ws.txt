===== 1
## Наблюдения

- Внутренние кулдауны и окна: AoE статусов — 0.25 с ICD (шанс 50%, радиус 3 м); взрыв при статусе на игроке — 3 с ICD (радиус 3 м); смена стихии — окно 1.5 с, возврат КД 2 с; крит после уклонения — 3 с; ярость после удара — 5 с (перезапуск при новом ударе); серия прыжков — сброс через 5 с без прыжка; подъём без урона — 10 с; рывок первой минуты — 60 с; обновление золота/кристаллов — 1 с задержка на объединение.
- Стаковые механики: прыжки +15%/каждый (потолок +100%); рывки +5% (потолок +15%); разные стихии +4%/(n−1); безупречные боссы +10% без предела; золото 0.04%/монету (потолок 20%); кристаллы 0.01%/штуку (+2.01% базово); проклятые +3%/+5%/+1%+15HP/…; инвентарь +1%/предмет.
- Общий порог HP «критическое здоровье»: 0.3 (≤). Реликвии на пороге: броня +20%, крит +20%, урон +15%. Реликвия «полный HP» — порог 1.0 (≥).
- Типы модификаторов: большинство «урон +X%» — множ. приоритета 10; шанс крита/броня/скорость анимации/уровни статусов — адд.; «потолок урона» и «шанс крита 100% после уклонения» — «перезапись»; урон крита +800% и −75% — адд. и позднее умножение.
- Условия «все умения»: везде где написано «кроме статусных» — по признаку «статусный эффект»; «кроме базовых и рывка» — по ID умения (содержит Basic / Dash). Список для data-схемы: фильтр умений (все / без статусов / только базовые / только не-базовые / по стихии / только прыжковые).
- Жизненный цикл: большинство реликвий снимают свой мод в деактивации; «деактивация» вызывается и при упаковке в группу (потом активация снова); при выбросе проклятых и т.п. подробности — в 14.
- Уничтожение при выбросе: только у «урон при полном HP» и «безупречные боссы»; обе при получении полностью лечат при каждой активации.
- Хаб-ограничения: только «проклятая реликвия каждого этажа» (hubOnly). Пул/цены — в 09-loot.
- Группы (контейнеры): «пять счётчиков арканов», «пять аур», «пять спутников-таранов» без собственного эффекта; расширяют инвентарь (контейнер = 1 слот, но для «броня от числа реликвий» считается как число частей). Сборка происходит при добавлении второй части: часть вызывает «создание группы», группа забирает части в свой внутренний инвентарь и они снова активируются.
- Группы по эффекту (в других кусках): шансы статусов (6, включает «урон по статусным целям»), иммунитеты (5), сопротивления (5), золото (5: урон/броня от золота и т.д.), «с проклятыми» (3), спутники (5), счётчики арканов (5), ауры (5), призывы (6), скидки (5), локаторы (3), базовая атака (5).
- Параметры data-схемы (поля, общие для многих): hp_threshold (0.3/1.0) + comparison, mod_type (add/mult/late_mult/override), value, per_count + cap, source_count (проклятые / инвентарь / золото / кристаллы / разные стихии / арканы стихии), duration, icd, chance, radius, element, skill_filter, once_per_pickup_effect (полное лечение / очистка инвентаря / выдача золота), debounce_sec (1.0), curse_penalty (второй блок модов).
- Экономические: цены в золото ×1.5 (две реликвии), потеря 5 золота за удар, долг 250 (+ceil 10%/сцену), покупка за HP/кристаллы, 2/3 золота за аркану.
- Кооп: «напарники» (+5/+12.5/+15%), «длительность оглушения босса» (снятие при владении у обоих).

## open_questions

- Реальный смысл «брони» (доля снижения урона?) и приоритетов — определяет 14-stat-modifiers; в каталоге указано как «+X% (адд.)».
- AoE статусов: срабатывает на каждый тик DoT или только на нанесение/наложение? В коде — глобальное событие DoT, момент тика не проверен.
- Спутник-таран: величина урона и параметры префаба неизвестны (в коде только поведение).
- Реликвии с полным лечением при получении (урон при полном HP, безупречные боссы): лечат на каждой активации, в т.ч. при смене этажа/упаковке? Не проверено.
- «Ссуда»: как долг уходит при нулевом золоте; расчёт процентов — каждая загрузка игровой сцены, включая босс-этажи?
- «Баланс арканов»: какие слоты входят (весь массив assignedSkills включая базовую и рывок или только арканы).
- Шкала овердрайва: единицы (0–100), +15 за событие — точное расхождение «ready» (режим активен) и «шкала полная».
- Уровень стихийных статусов у воздуха/воды в «уровень +1» — у воды нет уровня в коде (только огонь/воздух/земля/молния).
- «Платить кристаллами»: условие «проклятых меньше 12» выглядит как копия лимита инвентаря, а не логичной проверки.

===== 2
## Наблюдения

- Внутренние кулдауны: рывковое уклонение->овердрайв 0.25 с; сброс вражеских снарядов 16 с; уклонение после удара: действие 2.5 с, КД 30 с; сброс КД при HP ≤30%: действие 5 с, КД 10 с (общий); безлимит рывков после убийства: 6 с, ICD = длительность; броня после удара 3 с с обновлением; эхо-удар 0.1 с задержки; взрыв при проклятом убийстве 0.15 с.
- КД, живущие между уровнями (статика по игроку): «уклонение после удара» и «сброс КД при низком HP»; «банк урона от карты» — на забег; «заряд спасения от смерти» — на уровень (сбрасывается при загрузке уровня).
- Порог низкого HP = 30% (константа полосы здоровья), общая для трёх реликвий; параметр порога HP нужен схеме (порог, оператор сравнения, значение мода).
- Общая схема «мод стата»: поля {стат, значение, тип (адд./множ./поздний множ./переопределение), фильтр умений (все нестатусные / без статусов и базовых / без статусов, базовых и рывка / только рывок / только усиленные / только неусиленные), приоритет}. Приоритет по умолчанию 10; у переопределений 0 или 5; у усиления — 40/50.
- Базовые классы-«шаблоны»: ModWithHP (порог HP + оператор + мод), ModWithKills (учитывает только «чистые» убийства: враг, не мини-слизень, не призванный, без призывателя), OnTakeDamageItem (хуки: вход, событие, реальный урон, до щита), счётные реликвии (число открытых умений стихии считается один раз при активации).
- Группы-контейнеры (combineOnly, destroyOnDrop): при получении второго члена группы (достаточно двух) все члены убираются из инвентаря внутрь группы, а одиночные эффекты отключаются (проверка «создана ли группа»). Размеры: скидки 5, защиты 5, иммунитеты 5, шансы статусов 6, спутники 5, поля 5, счёт арканов 5.
- Сборка «огонь+лёд»: две проклятые реликвии при получении второй исчезают и порождают сборную; в пуле исключения не дают выпасть сборной напрямую.
- Реликвии NPC-лекаря (combineOnly): пул из 7 (без группы скидок) или 6 без «лечебных по 25» (если группа скидок уже есть и этот член в ней); при группе без этого члена он выдаётся первым; лекарь забирает случайное стандартное умение и роняет 3 сердца (по жетону — 5 сердец).
- «Проклятия хаба» (hubOnly) модифицируют забег целиком: враги, игроки, призванные; «99 урона» снимается на финальном боссе.
- Удвоение врагов (проклятие хаба) реализовано флагом уровня; нужен параметр «множитель числа врагов».
- Усиление (empower): выдаётся булевым модом с приоритетом; снимается при сбросе умения; «усилить базовую» и «усилить рывок» привязываются к первому подходящему слоту и переносятся при смене.
- Крит-флаг пустышки не умножает урон — только ставит признак; множитель крита идёт по честному броску.
- Реликвии «на этаж/уровень»: заряд спасения от смерти, вылечить 10% на загрузке, усиление случайной аркана, банк карты, компас выхода.
- Спутники: общие параметры (радиус обнаружения 7, зарядка 0.5 с, рывок 7, ICD 2 с + [0,1) с); отличаются стихией и радиусом орбиты (огонь −0.5, молния −0.25, земля +0.25, вода +0.5, воздух 0).
- Не зарегистрированы (UNUSED): рывковый урон ×2, две огненные бомбы, ледяная волна при овердрайве; также абстрактные базы.

## open_questions

- Когда именно «овердрайв готов» (событие с флагом готовности) — при заполнении шкалы или при активации? Поведение «волны» зависит от этого.
- В «банке урона от карты» порядок на загрузке уровня (сначала обновление, затем банкование) может банковать значение нового уровня, а не прошлого; нужно сверить с поведением карты при загрузке.
- Округление «+20% зарядов» (ExtraSkillCharge) определяется системой перезарядки — не прочитано.
- Что такое «минус» у проклятого компаса выхода: в коде виден только флаг проклятия.
- Расчёт числа арканов в счётных реликвиях — по всем «открытым» состояниям умений игрока (не только экипированным) и фиксируется при активации, не обновляется; проверить влияние на повторную активацию.
- Урон огненных всплесков, бомб, спутников, полей — из данных умений (не из реликвий); числа здесь не приведены.
- Влияние проклятия «99 урона» на урон от статусов (исключены) и на щиты/броню требует проверки в 14-stat-modifiers.

===== 3
## Наблюдения

- Внутренние кулдауны и окна: неуязвимость после 3 ударов - окно 3 с между ударами, длит. 3 с, КД 30 с; спасение от смерти - 2.5 с (он же ICD), шанс x0.5 после каждого срабатывания; щит на 5 ударов - окно 2 с на 1 заряд; потеря арканы/реликвии при ударе - КД 3 с; точный повторный рывок - ожидание 0.0667 с + окно 0.0667 с; пауза затухания сигнатурного заряда 0.75 с; скорость за кулдауны - 2.5 с; регенерации 2 HP/1 с и 3 HP/0.75 с.
- Накопительные максимумы (по забегу, статическое хранилище по игроку, сброс при начале нового забега, переживает выброс/повторный подбор): +3 за лечение до +75; +2 за удар до +75; +3 за удар до +100 (сборная); по убийствам: HP -50% -> +50% (шаг 1 п.п., 100 убийств), урон +50% / кулдаун +25% (шаг 0.25 п.п., 200 убийств) - эти счётчики сбрасываются при каждом (де)подключении.
- Единый порог «низкого HP» для регенерации - 30% макс. HP (равен порогу мигания полосы HP в HUD); порог урона для масштабирования - 50 HP (абсолютный).
- Рецепты/сборные: набор-выпускной (2 части), набор-единорог, лёд-пламя, вампирский набор, набор-фокусник, растущий-HP-с-регеном, а также идеальный локатор. Схема единая: при подключении части проверяется наличие второй; если есть - вторая и эта удаляются (принудительно), сборная выдаётся мимо лимита инвентаря, собственный эффект части не применяется.
- Групповые реликвии: при добавлении второго компонента группы создаётся групповая реликвия (мимо лимита), компоненты переходят во внутренний инвентарь и дальше считаются одним предметом. При выбросе/отключении группа выбрасывает компоненты по одному (если владелец жив).
- Глобальные (не личные) модификаторы: множитель золота (+15% / -50% / +15%), плоский бонус кристаллов (+1), число выпадающих реликвий (x2), шанс сердец (+50%), общий кошелёк (кристаллы, золото). В кооперативе мод снимается, когда он отсутствует у обоих игроков.
- События-коридоры для data-схемы: «на входе уровня», «на завершении загрузки», «на получении лечения», «на фактическом уроне», «на убийстве», «на крите», «на использовании умения», «на рывке», «на зачислении кристаллов», «на смерти босса», «на покупке слота лечения».
- Часть реликвий меняет СЧЁТ других (Защита-считает-защиту, усиленные арканы, арканы-перемещения): хранить критерий «категория / флаг умения» как параметр.
- Параметры схемы, общие для многих: kind_of_stat (макс. HP / урон / скорость / кулдаун / шанс крита / отбрасывание / длительность / заряд сигнатуры), value, mod_type (адд./множ./поздн. множ./override), skill_filter (все / без статусов / без базовых и без статусов / без базовых-рывка-статусов / только перемещения / только ближние / только снаряды / только баффы / стихия или под-стихия), threshold_hp (0.3 / 50 абс. / 0.1 по умолчанию базы), icd_seconds, duration_seconds, stack_step, stack_max, per_floor_once, chance, chance_decay_factor, cursed_flag, hub_only, destroy_on_drop, one_shot.
- Нерегистрированные (мёртвый контент): GoldOnBossCombo, IgnoreHurtKnockbackDown, KnockbackUpForAll, а также база GlassItem.
- JustFrameDash несовместима по смыслу с проклятием «без скольжения после рывка»: для повторного рывка нужно именно состояние скольжения.
- Лечебные события и обнуление: проклятие «полное HP, лечение отключено» обнуляет входящее лечение; «макс. HP за лечение» срабатывает на событии входа, до обнуления - на нём стоит порядок подписчиков (не гарантирован).

## open_questions

- Направление эффекта на кулдаун у проклятого «урон и кулдауны растут с убийствами»: положительный множитель стата кулдауна, по смыслу - рост кулдауна (минус), но формально не подтверждено.
- Проклятый «x3 отбрасывания»: в коде условие сравнивает поле с литералом-строкой вместо значения поля, поэтому, вероятно, никогда не срабатывает (мёртвая логика). Нужно решение: реализовывать задуманное (x3 отбрасывания, 0 < значение <= 40) или нет.
- Смысл «отмены» вражеских снарядов базовой ближней атакой (скрипт на объекте атаки): уничтожает снаряд или отражает - в коде этого куска не видно.
- Что именно считает счётчик убийств: событие убийства вызывается и для убийств не от владельца (кроме падения, где проверяется категория умения)? Видны только фильтры «не миньон/не мини-слизь».
- Единица плоского бонуса кристаллов (+1): добавляется к каждому дропу кристаллов (по данным цикла выпадения - ко всем броскам, включая гарантию) - нужно уточнить в спеке 09.
- Проклятие «HP в золото»: урон проходит через общий обработчик получения урона (сработают ли щиты, неуязвимость, реликвии «при уроне» - вероятно да), может ли убить.
- Радиус зоны молнии и выбор цели (случайная в радиусе или первая) - берётся из ассета, в коде нет.
- Колесо стихий (слабость боссов): таблица слабостей берётся из другого модуля; здесь только ссылка.
- Не вычислено, как «усиленное» состояние умения (от убора) меняет эффект умения - зависит от описания конкретных арканов.
- Нормализованное снижение кулдауна JustFrameDash: формула даёт долю от полного кулдауна (0.15 и далее), проверить на конкретных числах при реализации.
- Колесо «последний удар по боссу» при убийстве слабой стихией: учитывается ли удар партнёра в кооперативе (владелец не проверяется).

===== 4
## Наблюдения

- Шкала «разгона» (в референсе — шкала сигнатуры): 0–100, минимальное значение 0.01; в режиме накопления убывает на 4.5 ед/с, в режиме готовности (при 100) — на 10 ед/с (~10 с); при готовности кулдаун сигнатуры сбрасывается; применение сигнатуры даёт 0.25 с неуязвимости и сбрасывает шкалу. Реликвии шкалы: убывание накопления → 0, убывание готовности → 0 (готовый разгон не гаснет сам), набор +15%, у проклятых +30% или +5% за проклятую, «двойное применение» (пауза 0.75 с, убывание +50%, набор −25%), «в лечение» (25 HP вместо ультимейта), «сброс кулдаунов», «в щит» (35 ед.), «от урона» (+урон ед.).
- Внутренние кулдауны: гарантированный крит арканы — 7 с (окно 2.5 с); щит-отражатель — перезаряд 30 с на 1 заряд; регенерация — задержка 8 с, тик 0.05 с (+1 HP); катаклизмы — интервал 2.5–4 с; пауза разгона при двойном применении 0.75 с.
- Стаки/накопления по игроку на весь забег (static-словарь по id игрока, чистится сбросом забега): растущий урон сигнатуры (+1% за применение, предел +50%), броня от полученного урона (2% + 0.01%/ед., предел накопления 1000). Накопление хранится вне экземпляра реликвии и переживает выброс/подбор.
- Накопление на экземпляре (не по игроку): урон за кристаллы (+0.1%/кристалл, предел +20%), копилка (отсчёт с момента подбора).
- Расходуемые при выбросе реликвии (destroyOnDrop): копилка, сундук аркан, сундук реликвий, запасная жизнь, контейнер-группа. Эффект выпадения срабатывает только если игрок жив и сцена игровая. Формулы: сундуки N = clamp(3×круг + 2×ярус + 1, 1, 5); копилка V = min(20, 9×круг + 3×ярус + этап) → золото min(1000, 50V), кристаллы min(50, 5V), сердца min(5, V).
- Группы-контейнеры (общий механизм): при подборе второго члена группы создаётся контейнер (не покупается, без лимита), члены уходят во внутренний инвентарь и продолжают работать, показывают прогресс n/N; выброс контейнера выбрасывает всё. Группы в этом куске: лёгкая-атака-пять (воздух, земля, огонь, молния, вода), аура-пять (одна — яд), шанс-статуса (6, одна — яд), иммунитеты-пять (одна — яд), скидки-пять (одна — на реликвии), с-проклятыми-три (одна — перезарядка), локаторы-три (в составе сборки).
- Сборки (рецепты, по идентичному правилу «при подборе второго компонента заменить оба на результат без лимита»): набор отбива = лечение при низком HP + оглушение (проклятая, принудительное снятие); итоговый набор отбива = набор отбива + отбив с разгоном; единорог = радужный след + маска-лошадь; идеальный локатор = три локатора (в группе); хаос-сборка — вне куска.
- Реликвии отбива сами включают способность отбива (булев мод); все срабатывают только на «новый отбив» (предыдущее состояние не отбив). Величины: 10 HP (только ≤30% HP), 15 HP, 20 HP, +25 разгона, +30 разгона.
- Проклятые реликвии (isCursed) нельзя убрать обычным путём; hub-only — добываются только из пула хаба: ямы, барьеры, катаклизмы, бочки, стихийные враги, у всех 1 HP, обмен умений, статусный иммунитет, перезарядки у всех. Почти все — «модификаторы забега» без своих чисел-бонусов: плата и польза разведены по игроку и врагам.
- Реликвии «глобального» действия на врагов (нужны подписка на появление врагов и повторное применение к уже живым): 1 HP, статусный иммунитет, перезарядка у всех, шанс крита врагов. Реликвия запрета умений переприменяется на каждой загрузке уровня.
- Параметры для data-схемы (общие): множитель мода (значение + тип «адд./множ.»); приоритет мода (10 по умолчанию, 5 у иммунитетов, 0 у 1 HP, 2 у перекраски); порог HP (0.3 для «низкого», 0.85 для регенерации) и тип сравнения; шанс срабатывания; шанс/число/предел накопления (шаг, потолок); внутренний кулдаун и длительность окна; номер группы и id рецепта; число зарядов щита и время перезарядки; список типов врагов для запрета; формула сундука (круг/ярус/этап, клапаны 1..5); долгие эффекты — id стат-поля (урон, перезарядка, разгон, шанс крита, крит-урон, шанс статуса, уровень статуса, оглушение, скорость бега), фильтр умений (все, кроме статусов, без лёгкой атаки, снарядные, ближние, только хаос-стихия).
- Фильтры умений: «все кроме статусов» (подавляющее большинство), «снарядные», «ближние», «хаос-стихия»; реликвия «крит арканы» исключает лёгкую атаку, рывок и ультимейт.
- Шанс лёгкой атаки: 0.45/(макс. число ударов комбо + 0.5) на каждый удар — у 3-ударного комбо ≈12.9% на удар; цена связана с длиной комбо.
- Побочный эффект: выключение регенерации (при снятии «регенерации при высоком HP») обнуляет щит; при переходе HP через порог 85% регенерация включается/выключается, и щит тоже обнуляется.
- Выбросы/сбросы: при снятии реликвии «лечебная лавка не слабеет» параметр возвращается к 5% за покупку; «скидки» снимают мод со всех выставленных позиций. Игровые модификаторы хаба (ямы, бочки) обратимы: шансы возвращаются к стандартным.

## open_questions

- Плюс проклятой реликвии «уровни без ям»: код только убирает ямы; бонус (если есть) задан вне реликвии, возможно, лишь в цене/пуле проклятых.
- Направление эффекта «−25% (множ.)» на словарях стихий и сопротивления статусам у владельца в реликвии «все враги стихийные»: в коде мод множителя; считаю, что это снижение получаемого урона/статусов, но не проверено по Health.
- Что именно значит «ReduceTimePercentage(0.1)» в реликвии финала комбо — 10% от полной или от оставшейся перезарядки.
- Реликвия «гарантированный крит арканы»: повторное включение таймера при уже идущем кулдауне — рестарт или нет (в коде присваивание true к уже работающему секундомеру).
- Шкала арканных слотов у реликвии хаос-сборки: 6 назначенных + «запасной слот» — подтвердить, что их 7 и что ровно это порог оформления (≥7).
- Дальность/радиус и точные размеры барьера-гасителя снарядов и щита-отражателя берутся из префабов, не из кода реликвий.
- В реликвии катаклизмов не видно урона/ширины: берутся из данных врагов по id (метеор, давление, валун, молния, буря), число попаданий бури 16 и длительность 4 с заданы в коде.
- Сохраняется ли накопленное значение «урона за кристаллы» между забегами (оно в экземпляре, но экземпляры создаются при подборе).
- Поведение «улучшенных аркан» в сундуке аркан: параметр улучшенности включён в вызове дропа; число — N из формулы (проверить в 09-loot).
- Тип (стат/множ.) «шанса крита +15%/+30%» и «шанса статуса +6.25%» — это обычные адд.-моды (тип по умолчанию Additive).

===== 5
## Наблюдения

- Внутренние КД (таймер): RootShield, ShockShield, StunShield — по 16 с; ResetCooldownsOnHurt — 30 с (не в пуле); RetributionHeal — окно 2 с с продлением и бюджетом 75 % урона, лечение 10 % от нанесённого. ResetCDChance — шанс 20 %, без КД.
- Все 16-секундные «при ударе» работают от фактического урона (после щитов); срабатывают и на удар с нулевым уроном? (open_questions).
- Стандартные множители и значения-«шаги»: шанс статуса +6.25 % (огонь/шок/…, 0.1 у замедления), уровень статуса +1, стихийный урон +12 % (множ.), сопротивление ×0.75 (урон и статус), стихийное «счётчик арканов» 2 % + 0.5 % за аркану, лечение призыва +3/убийство.
- Призыв: КД −25 %, урон +20 %, длительность +50 %, число +1, лимит +2, лечение +3 — все шесть вкладываются в группу «призыв»; проклятая версия +20/+50/+50(КД ухудшается).
- Группы (GroupItem): combineOnly, isGroupItem, destroyOnDrop = true, не продаются; при подборе второго члена создаётся группа сверх лимита инвентаря, все члены переносятся в её внутренний инвентарь; при снятии группы члены выбрасываются на пол (кроме смерти — не выбрасываются). Члены в группе после слияния сохраняют эффекты (активация члена пропускается только в момент создания группы и затем срабатывает от внутреннего инвентаря).
- Члены ряда групп активны независимо; ряд реликвий (аура, familiar, скидка, локатор, счётчик арканов) не создаёт дубль эффекта при слиянии (проверка «группа создана»).
- Типы групп по составу: шансы статусов (6), спутники (5), ауры (5), сопротивления (5), иммунитеты (5), скидки (5), «от проклятых» (3), локаторы (3, рецепт «полный» из 4), золото (5), счётчик арканов (5), призыв (6), срабатывание на базовой (5).
- Рецепты (сборные combineOnly): комплект странника (кукла+фигурка), лечебный комплект (кровопийство + лечение при крите), радужный бегун (след + маска), полный локатор (4 локатора); кукла/фигурка/кровопийство при подборе, найдя вторую половину, сами собирают комплект (результат выдаётся с ignoreMax).
- Воскрешение: выбирается доступная реликвия с минимальным priority (кольцо 0, арканная 10); после использования расходуется; воскрешение — 25 % HP по умолчанию, арканная версия 5 % × (число потерянных + 1).
- ReplaceNonCursedRelics меняет флаг проклятости на «чисто сборных» реликвиях и подменяет предметы; требует поля data: лимит инвентаря 12, HP за проклятую 10, скорость за проклятую 2 %, число повторных попыток 3.
- hubOnly + проклятые: VampireSoul и SlowProjectiles; SlowProjectiles не регистрируется, VampireSoul — зарегистрирована.
- Нерегистрированные (мертвый контент): ResetCooldownsOnHurt, ShieldUp, SigEleDamageUp, SlowProjectiles, StunDurationUp, SummonArmorItem, WindSlash; базовые классы: ResurrectItem, RoomLocatorItem, SevenFlush, SignatureModItem.
- Жетоны (7) — только ярлыки в инвентаре; логика в NPC (банкир, лекарь, портной, тасовщик, колодец, пиньята, проклятый магазин); один жетон выбирает тип особой комнаты следующего уровня (первый найденный).
- Условие SevenFlush: слоты — все назначенные (в том числе базовая/рывок?) и запасной слот одной стихии; пересчёт на каждое изменение навыков.
- Параметры для data-схемы: порог доли HP, множитель (множ./адд.), приоритет мода, длительность окна, ICD, макс. стаков, шаг/процент шанса, список затрагиваемых типов умений (все / без статусов / без базовых и рывка / призыв / движение / сигнатурная / стихия), стихия, тип статуса, число повторов, id группы/рецепта, флаги (isCursed, hubOnly, notForSale, combineOnly, destroyOnDrop).
- Сигнатурные моды (кукла/фигурка/комплект) применяются к текущей сигнатурной аркане и переносятся при смене.

## open_questions

- ReplaceNonCursedRelics: точный смысл «CursedCount < 12» и порядок подсчёта при группах; возвращаются ли вложенные члены групп после удаления.

- SpeedBoostOnSurvivalClear: имя говорит о зачистке выживания, код — только −15 % КД движения.

- ResetCDChance, RootShield, ShockShield, StunShield, ResetCooldownsOnHurt: срабатывают ли на урон 0 (SequenceDefense проверяет урон > 0, остальные — нет).
