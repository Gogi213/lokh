# Superpowers policy

Superpowers is selective optional tooling beneath explicit user instructions,
`AGENTS.md` and canonical project policy. There is no mandatory startup or
`using-superpowers` bootstrap. Choose a concrete useful procedure; do not load
a bundle because a generic skill says it always applies.

- `DevelopmentWorkflow.md` owns behavior agreement, useful tests and run
  selection. TDD/RED-GREEN-REFACTOR and pressure/model-eval workflows need explicit
  request and selected commands. Never delete implementation or recreate a
  baseline to satisfy a preferred sequence.
- `PlanWorkflow.md` owns plans and Goals. Reuse settled decisions; a skill adds
  no spec/plan/commit/approval stage. Ordinary work needs no durable artifacts.
- `Subagents.md` owns delegation and mandatory independent H0/H1/Capital reviews.
  Select actual expertise, not every matching role. Other chats retain ownership.
- A skill grants no runs, Git/remote writes or account/order actions.
  Runtime/live actions require separate exact task-scoped authorization
  even when listed in a plan. Keep implementation and observed checks distinct;
  successful checks stop under the canonical consent/repeat rule.

Keep the installed plugin/cache unchanged. This file owns selection of its
procedures; do not copy vendor skills or add a competing workflow system.
