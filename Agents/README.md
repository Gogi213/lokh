# CXET agent system

Root `AGENTS.md` is the entry point. Read inherited/nested rules for the
selected scope and load detailed policy only when its trigger applies.
Follow explicit user instructions and instruction priority for conflicts; use the
canonical owner, keep compatible safety constraints and report only material
unresolved conflicts. A route/link does not load every referenced document.

## Owners

| Question | Owner |
|---|---|
| Which rule applies? | `RuleIndex.json` |
| Architecture, public contracts, versions, storage, compiler and source graph | `GlobalContracts.md` |
| Behavior agreement, tests, run consent, safe attempts and evidence | `DevelopmentWorkflow.md` |
| Planning, native Goals and requested durable plan/state lifecycle | `PlanWorkflow.md` |
| Selecting expertise for uncertain ownership | `RoleRouter.md` |
| Compiled hot route and H0/H1/C/D restrictions | `HotPathFastLane.md` |
| Delegation, simplicity participation, model routing and independent H0/H1/Capital reviews | `Subagents.md` |
| Concise result, evidence labels and severity | `ReportFormat.md` |
| Domain-specific internal review lenses | Relevant `Roles/*.md` |
| Selective optional Superpowers procedures | `Superpowers.md` |
| AWS and runtime secret resolution | `AwsWorkflow.md` |

Common context contains only root AGENTS. Load Subagents for delegation,
mandatory review or model-routing questions, and reporting rules when producing
a non-trivial report. Capital explicitly retains inherited financial/H0/review
constraints already offline. Ordinary grep does not trigger an agent-policy load.
Read unchanged rules once per context; reuse bounded findings and existing workers.

For Risk S changes, apply the lightweight path in DevelopmentWorkflow without
extra plan artifacts or unrelated domain loads. First approval of an exact check
package lasts for the active task's justified runs; local workflow/utility checks
run directly, while native build checks retain their owner cache and lock.
Subagents.md owns the cascade and code-simplicity participation within the configured session limit.

## Local tools and skills

`cxet_local` tools under `tools/Codex/` select static context and source
anchors. They do not run builds/tests/Git/network/live/account actions or
prove readiness/latency. Readiness sections use exchange-owned Config.cpp;
common anchors and token matches are context, not caller-chain evidence.
If unavailable, inspect the same bounded anchors manually, without starting
a server implicitly.

Root skills live in `.agents/skills/`: context routing; exchange readiness;
hot-path/parser/transport audits; runtime contracts; requested durable workflow
and existing-plan audit. App-owned skill sources stay under their app until
separately promoted. Skills select procedures without adding authority or stages.

For selected policy verification propose `python3 tools/Codex/CheckAgentPolicy.py`;
when context routing changes, also propose
`python3 tools/Codex/CxetContextIndex.py validate --format summary`.
Run only exact user-selected commands under DevelopmentWorkflow.
